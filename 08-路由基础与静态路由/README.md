# 第 08 章 · 路由基础与静态路由

> **一句话定位**：把「报文怎么找到下一跳」讲透——从路由表结构与最长前缀匹配算法，到静态/默认/汇总/浮动静态路由的配置与取舍，读完能独立设计一套带备份的静态路由方案，并能根据 `show ip route` 与 `traceroute` 定位环路、单通与路由黑洞。
> **前置知识**：第 06 章 IPv4 地址与子网划分 ｜ **难度**：★★☆ ｜ **建议投入**：140 分钟

## 一、学习目标

1. 能说出路由表七大字段（目的网络/掩码/下一跳/出接口/度量/管理距离/标志）各自的含义。
2. 能手工执行最长前缀匹配算法，并解释「前缀 → AD → 度量」的三级比较顺序。
3. 能配置静态路由、默认路由 `0.0.0.0/0`、汇总路由与浮动静态路由，并说明各自的适用场景。
4. 能背出常见路由来源的 AD 取值，并说出 Cisco 与华为默认值的差异。
5. 能理解路由递归、等价路由负载分担与策略路由（PBR）的执行位置与匹配顺序。
6. 能通过 TTL、ICMP 超时报文与 traceroute 输出，判断网络中是否存在环路或黑洞。

## 二、核心概念总览

```
                    ┌─────────────────────────────────────────────┐
   控制平面 RIB     │  路由表（Routing Information Base）          │
   （怎么找路）      │  目的网络 | 掩码 | 下一跳 | 出接口 | 度量 | AD │
                    └───────────────────────┬─────────────────────┘
                                            │ 最佳路由下刷
                                            ▼
                    ┌─────────────────────────────────────────────┐
   数据平面 FIB     │  转发表（Forwarding Information Base）        │
   （怎么转发）      │  按「最长前缀匹配」查表，硬件线速转发          │
                    └───────────────────────┬─────────────────────┘
                                            │
        ┌───────────────┬───────────────────┼───────────────────┬──────────────┐
        ▼               ▼                   ▼                   ▼              ▼
   ┌─────────┐   ┌───────────┐      ┌─────────────┐    ┌──────────┐   ┌──────────┐
   │直连路由  │   │静态路由    │      │默认路由      │    │浮动静态   │   │汇总/黑洞 │
   │AD 0     │   │AD 1       │      │0.0.0.0/0     │    │AD 10 备份 │   │null0 防环│
   │接口 up  │   │手工/默认   │      │兜底出口      │    │主挂自动切 │   │聚合副作用 │
   └─────────┘   └───────────┘      └─────────────┘    └──────────┘   └──────────┘
```

上图的左边是**控制平面**（路由器之间交换信息、算出最佳路径，存进 RIB），右边是**数据平面**（把最佳路径下刷成 FIB，硬件按最长前缀匹配线速查表）。本章的五类路由来源按「可信度」（AD 越小越可信）排成一条链：直连 0 最可信，静态 1 次之，然后是各种动态协议。**所有转发决策最终都归结为一句话：在匹配到的所有前缀里，取最长的那个；长度相同则比 AD；AD 相同则比度量。** 数据平面的转发不感知协议来源，只认 FIB 里的表项。

## 三、机制详解

### 3.1 路由表结构与各字段含义

一条路由表项至少要回答五个问题：去哪儿（目的网络 + 掩码）、怎么走（下一跳或出接口）、多可信（管理距离）、多贵（度量）、谁给的（协议来源）。

| 字段 | 含义 | 说明 |
|---|---|---|
| 目的网络 + 掩码 | 目标网段与它的前缀长度 | 掩码越长前缀越具体，优先级越高 |
| 下一跳 Next Hop | 交给哪个邻居的 IP | 必须是可达地址（直连或递归可达） |
| 出接口 Outgoing Interface | 从哪个口发出去 | 以太网上通常「下一跳 + 出接口」都给 |
| 度量 Metric | 协议内部的开销 | OSPF 用 Cost、RIP 用跳数、EIGRP 用复合度量 |
| 管理距离 AD | 跨协议的可信度 | 数字越小越可信，只在同前缀长度时比较 |
| 标志位 | 路由来源与状态 | `C` 直连、`L` 本地、`S` 静态、`S*` 静态默认、`O` OSPF、`D` EIGRP、`R` RIP、`B` BGP |

Cisco `show ip route` 输出示例：

```
Codes: C - connected, S - static, O - OSPF, R - RIP, * - candidate default
       > - selected for forwarding

S*   0.0.0.0/0 [1/0] via 203.0.113.1
     192.0.2.0/24 is variably subnetted, 2 subnets, 2 masks
C       192.0.2.0/24 is directly connected, GigabitEthernet0/1
L       192.0.2.1/32 is directly connected, GigabitEthernet0/1
S       198.51.100.0/24 [1/0] via 203.0.113.2
O       10.0.0.0/8 [110/20] via 203.0.113.2
```

方括号里的 `[1/0]` 是 **[AD/度量]**，`>` 表示这条被选中下刷到 FIB，`*` 表示候选默认路由。**没有 `>` 的路由不会转发**，这是排障时最容易忽略的细节。

### 3.2 最长前缀匹配算法

算法本身极其简单，但必须严格按顺序执行三步：

1. **取最长前缀**：在所有匹配目的地址的路由中，选前缀长度最大的。前缀越长越具体，与 AD、度量无关。
2. **同长度比 AD**：前缀长度相同时，选管理距离最小的（越可信）。
3. **再比度量**：前缀与 AD 都相同，选度量最小的；三者全同则形成**等价路由**，按哈希做负载分担。

**例题**：路由表有 `192.0.2.0/24`（直连，AD 0）、`192.0.2.64/26`（静态 AD 1）、`192.0.2.64/26`（OSPF AD 110）、`0.0.0.0/0`（静态 AD 1）。查目的 `192.0.2.70`：

```
匹配的路由：/24、/26（静态）、/26（OSPF）、/0 —— 共 4 条
第 1 步：最长前缀 = /26（两条），淘汰 /24 与 /0
第 2 步：同长度比 AD → 静态 AD 1 < OSPF AD 110，淘汰 OSPF
第 3 步：胜出 = 192.0.2.64/26 via 静态
```

**注意**：直连的 `/24` 被 `/26` 挤掉了——**具体优先压过可信度优先**。这是「为什么配了静态路由反而走错」的最常见原因。

### 3.3 直连路由与接口状态

直连路由由接口配置自动生成，**它的存在完全取决于接口的 up/up 状态**：

- 接口 `up/up`（物理与协议都起来）→ 自动生成两条：`C` 网段路由（如 `192.0.2.0/24`）与 `L` 本地主机路由（如 `192.0.2.1/32`）。
- 接口 `down/down` 或 `administratively down`（被人为 `shutdown`）→ 直连路由立即撤销，所有下一跳指向该网段的静态/动态路由也随之失效。
- 接口 `up/down`（物理通但协议不通，如以太网链路两端速率协商失败）→ 同样不生成直连路由。

**这条规则是浮动静态能工作的基础**：下一跳所在的直连网段一旦消失，指向它的静态路由就被撤销，备份路由才装上。

### 3.4 静态路由家族

| 类型 | 写法（Cisco） | 用途 |
|---|---|---|
| 普通静态 | `ip route 198.51.100.0 255.255.255.0 203.0.113.2` | 点对点或末梢网络 |
| 默认路由 | `ip route 0.0.0.0 0.0.0.0 203.0.113.1` | 兜底出口，匹配所有地址 |
| 汇总路由 | `ip route 192.0.2.0 255.255.252.0 203.0.113.2` | 一条覆盖 4 个 /24，见第 06 章 CIDR |
| 浮动静态 | `ip route 198.51.100.0 255.255.255.0 203.0.113.10 10` | 末尾的 10 是 AD，主路由挂掉才生效 |
| 黑洞防环 | `ip route 192.0.2.0 255.255.252.0 null0` | 丢弃命中汇总但无明细的流量，防环 |
| 递归静态 | `ip route 198.51.100.0 255.255.255.0 10.1.1.1` | 下一跳不直连，需先查到它的路由 |

**默认路由 `0.0.0.0/0`** 的前缀长度是 0，能匹配任何地址，但永远是最后被选中（因为最短）。它把「未知目的」交给上游，是末梢网络的标准配法。

**浮动静态的原理**：AD 只在「同前缀长度」时参与比较。主路由 `198.51.100.0/24` AD 1 与备份 `198.51.100.0/24` AD 10 前缀长度相同，AD 小的先入 FIB；主路由的下一跳不可达时被撤销，AD 10 的备份随即装入。**切换是可达性驱动的，没有协议计时器，通常在毫秒级。**

**路由递归**：当静态路由的下一跳不在任何直连网段时，路由器必须先递归查一次「到该下一跳怎么走」，并做最长前缀匹配，然后才把这条路由装入 FIB。若递归查询失败（找不到到下一跳的路由），这条静态路由**不会生效**。这也是「路由表里有这条，但 `show ip route` 里没有 `>`」的典型原因。

### 3.5 管理距离（AD）与 Cisco / 华为差异

| 路由来源 | Cisco AD | 华为 Preference | 备注 |
|---|---|---|---|
| 直连 Connected | 0 | 0 | 最可信 |
| 静态 Static | 1 | 60 | **两家默认值差异最大的一档** |
| EIGRP 汇总 | 5 | — | 仅 Cisco |
| eBGP（外部 BGP） | 20 | 255 | — |
| EIGRP（内部） | 90 | — | 仅 Cisco |
| OSPF | 110 | 10 | 华为 OSPF 优先于静态 |
| IS-IS | 115 | 15 | — |
| RIP | 120 | 100 | — |
| EIGRP（外部） | 170 | — | 仅 Cisco |
| iBGP（内部 BGP） | 200 | 255 | 最不可信之一 |
| 不可用 | 255 | 255 | 不装入路由表 |

**关键差异**：Cisco 里静态（1）优于 OSPF（110）；华为里静态（60）**劣于** OSPF（10）。同一份网络设计在两家设备上的选路结果可能不同，跨厂商组网时必须显式调整 preference/AD。

### 3.6 等价路由、负载分担与路由递归

- **等价路由**：前缀长度、AD、度量三者全同的多条路由同时装入 FIB。
- **负载分担方式**：默认按「源 IP + 目的 IP」等字段做哈希（Cisco 默认 `per-destination`，可改 `per-packet`）。**同一会话始终走同一条路径**，因为哈希输入不变——这就是「两条 1G 链路链路聚合后单条 TCP 只有 1G」的同一个原理（见第 04 章 LAG）。
- **路由递归**：BGP 的下一跳常常不直连，需要递归查到 IGP 路由；静态路由的下一跳若不直连同样要递归。递归深度过深会拖慢收敛，也会让「下一跳可达性」变得难以判断。

### 3.7 策略路由（PBR）与路由策略

| 工具 | 作用范围 | 匹配对象 | 典型用途 |
|---|---|---|---|
| 策略路由 PBR | **转发行为**（改变下一跳） | ACL、前缀列表、接口、长度 | 让特定源段走特定出口（如办公段走专线） |
| 路由策略（route-map） | **路由信息**（过滤/改属性） | ACL、前缀列表、AS_PATH、community | 控制哪些路由被引入、被宣告 |
| 前缀列表 prefix-list | 匹配路由前缀 | 网络号 + 掩码长度范围 | 比 ACL 更精确，支持 `ge/le` |
| ACL | 匹配报文五元组 | 源/目的 IP、端口、协议 | PBR 与 route-map 的基础匹配器 |

**PBR 的执行位置比路由表更早**：报文进入接口后先看有没有 `ip policy route-map`，命中就按 `set` 指令转发，**完全绕过路由表的选路结果**；未命中才走正常查表。因此 PBR 是排障时最容易被忽略的一环——「明明路由表对着，为什么流量走了另一条」十有八九是有 PBR。

**匹配顺序**：route-map 按序号（10、20、30…）从小到大逐条匹配，**第一条命中即生效**，不再看后面的；若所有条目都没命中，则落到**隐式 deny**（对路由策略意味着不匹配、对 PBR 意味着回退到正常查表）。

**前缀列表的 `ge/le`**：`ip prefix-list P permit 192.0.2.0/24 ge 25 le 26` 表示「前缀在 192.0.2.0/24 之内、掩码长度 ≥25 且 ≤26」，用于精确匹配子网。

### 3.8 TTL、环路与 ICMP 超时

**TTL（Time To Live）是 IP 层的最后一道防线**：

1. 发送方给出初始 TTL：Linux 默认 64、Windows 默认 128、多数网络设备 255。
2. 每台路由器转发前把 TTL 减 1。
3. 减到 0 时丢弃报文，并向源地址回 **ICMP Time Exceeded（Type 11, Code 0）**。
4. `traceroute` 正是利用这一点：第一组报文 TTL=1，第一跳路由器把它减到 0 后回超时；第二组 TTL=2，第二跳回超时……从而逐跳画出路径。

**环路的表现**：`traceroute` 输出里同一组地址反复出现（如 R1、R2、R1、R2…），且持续到第 30 跳仍不收敛；`ping` 表现为高时延或超时但途中设备 CPU/接口计数飙升。**TTL 只能限制环路的破坏，不能消除环路**——64 跳的转发资源已经被浪费掉了。

## 四、动手验证

**1) `route_lookup.py` → 最长前缀匹配**

```
目的地址：192.0.2.130   （二进制 11000000.00000000.00000010.10000010）
    [命中] /25 192.0.2.128/25     下一跳=203.0.113.3    AD=1   度量=0   来源=静态  >>> 胜出
    [落选] /24 192.0.2.0/24       下一跳=direct         AD=0   度量=0   来源=直连  淘汰：前缀 /24 短于胜出的 /25
    [落选] /0  0.0.0.0/0          下一跳=203.0.113.1    AD=1   度量=0   来源=静态默认路由  淘汰：前缀 /0 短于胜出的 /25
```

同时演示「同前缀长度比 AD」（`192.0.2.70` 命中 /26，静态 AD 1 挤掉 OSPF AD 110）与「等价路由」（`198.51.100.5` 两条同前缀同 AD 同度量）。脚本内断言了 8 个用例的胜出前缀与下一跳。

**2) `static_route_gen.py` → 静态路由生成与浮动静态切换**

```
场景 2：仅 L12 故障 down —— R1 切到浮动静态，但 R3 不切 → 单通
    [失效] /24 198.51.100.0/24    下一跳=203.0.113.2    AD=1   出接口=-      到 PC2 网段，主 → R2｜下一跳不可达（L12 down）
    [可用] /24 198.51.100.0/24    下一跳=203.0.113.10   AD=10  出接口=G0/2   到 PC2 网段，浮动 → R3 <<< 选中
  回程（PC2 → PC1）：PC2 → R3 →(L23) R2 →(L12 断) ✗  ← R3 的下一跳仍可达，没切
```

**结论**：浮动静态靠「下一跳可达性」触发；只配单端会出现「去程通、回程断」的单通。L12 与 L23 同时 down 后两端都切换，路径恢复全通。

**3) `loop_and_ttl.py` → 环路与 TTL**

```
第   1 跳：R1 收到并递减，TTL 剩余 63
第   2 跳：R2 收到并递减，TTL 剩余 62
...
第  64 跳：R2 收到并递减，TTL 剩余 0
>>> 结果：R2 收到 TTL=1，递减为 0 → 丢弃报文，回 ICMP Time Exceeded（Type 11, Code 0）
  null0 场景：2 跳，1.0 ms，报文立即被丢弃，回 ICMP Type 3
```

**结论**：环路不会被无限转发，但会吃满 64 跳才停；加 null0 防环后从 64 跳降到 2 跳。

## 五、关键字段 / 报文格式解剖

**ICMP 差错报文（Type 3 / 5 / 11）**

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| 类型 Type | 1 字节 | 差错类别 | 3 目的不可达、5 重定向、11 超时、12 参数问题 |
| 代码 Code | 1 字节 | 具体原因 | Type 3：0 网络不可达、1 主机不可达、3 端口不可达；Type 11：0 TTL 超时、1 分片重组超时 |
| 校验和 | 2 字节 | 校验整个 ICMP 报文 | — |
| 未使用 / 下一跳 MTU | 4 字节 | Type 3 Code 4 时为 PMTU | 1500、1400… |
| 原始 IP 首部 | 20 字节 | 触发差错的报文首部 | 用于源端匹配哪条流 |
| 原始数据前 8 字节 | 8 字节 | 含端口号 | 用于区分同一主机的不同会话 |

**IPv4 首部中与路由相关的字段**

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| TTL | 8 bit | 剩余可经过的跳数 | 初始 64/128/255，每跳 −1，为 0 丢弃 |
| 目的地址 | 32 bit | 查表键 | FIB 按它做最长前缀匹配 |
| 标志 DF | 1 bit | 禁止分片 | DF=1 时超 MTU 会丢包并回 Type 3 Code 4 |
| 首部校验和 | 16 bit | 每跳因 TTL 变化需重算 | — |

**路由表项（RIB）字段**

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| 目的前缀 | 32 bit + 前缀长度 | 匹配键 | 192.0.2.0/24 |
| 下一跳 | 32 bit | 转发目标 | 直连邻居地址或 `direct` |
| 出接口 | — | 从哪个口发 | G0/0 |
| 度量 Metric | 32 bit | 协议内开销 | OSPF Cost、RIP 跳数 |
| 管理距离 AD | 8 bit | 跨协议可信度 | 0/1/20/90/110/120/200 |
| 标志 Flags | — | 来源与状态 | C/L/S/S*/O/D/R/B、`>` 已选中 |

## 六、易混概念对比

| 概念 A | 概念 B | 核心区别 | 典型场景 |
|---|---|---|---|
| 控制平面 RIB | 数据平面 FIB | RIB 存所有候选路由，FIB 只存被选中的最优路由 | 查表转发 vs 路由计算 |
| 管理距离 AD | 度量 Metric | AD 跨协议比可信度，度量协议内部比开销 | 静态 vs OSPF 用 AD；OSPF 内部用 Cost |
| 默认路由 | 汇总路由 | `0.0.0.0/0` 匹配一切（长度 0），汇总路由匹配一个连续地址块 | 末梢出口 vs 聚合宣告 |
| 浮动静态 | 等价路由 | 前者靠 AD 差异做冷备（只有一条在 FIB），后者三项相同做热备分担 | 主备链路 vs 双上行负载 |
| 策略路由 PBR | 路由策略 route-map | 前者改「报文怎么转发」，后者改「路由信息怎么传」 | 源段分流 vs 路由过滤 |
| TTL 超时 | 目的不可达 | Type 11 表示跳数耗尽（通常环路），Type 3 表示找不到路 | 环路 vs 无路由/无监听 |
| 路由黑洞 | 路由环路 | 前者包被静默丢弃，后者包被反复转发直到 TTL 耗尽 | 汇总缺口 vs 下一跳互指 |

## 七、工程实践与最佳实践

1. **静态路由只在末梢与小型网络用**：网络规模超过十几台设备后，静态路由的维护成本会指数上升，应及时引入动态路由（第 09 章）。
2. **默认路由只配在末梢设备**：核心/汇聚设备配默认路由会把未知流量引向出口，一旦出口故障全网黑洞；核心应有明细或汇总路由。
3. **浮动静态的 AD 要拉开档次**：主路由 AD 1、备份 AD 10 是常用做法；若两者 AD 相同会变成等价路由做负载分担，失去备份语义。
4. **双向都要配对称的静态路由**：只配去程会产生「去程通、回程断」的单通，靠对称配置 + 双向 ping 验证。
5. **汇总路由必须配 null0 防环**：汇总会把缺口也宣告出去，用同前缀指向 null0 的静态路由兜底，避免流量被默认路由送回上游形成环路。
6. **下一跳优先用「下一跳地址 + 出接口」而非只写接口**：以太网是广播型多路访问，只写出接口会触发对每个目的地址的 ARP，且无法精确描述转发语义。
7. **跨厂商组网要核对 AD/preference**：Cisco 静态 = 1、华为静态 = 60；Cisco OSPF = 110、华为 OSPF = 10。同一设计在两家设备上选路可能相反，必须显式调整。
8. **递归静态路由要确认下一跳可解析**：下一跳不直连时，必须存在一条能到达它的路由，否则该静态路由不装入 FIB。
9. **启用 PBR 后要把它写进变更记录**：PBR 的优先级高于路由表，是「路由表对了但流量不走」的头号嫌疑。
10. **环路的最终定位靠 traceroute + 相邻设备路由表比对**：看到同一地址反复出现就沿路查每个设备的 `show ip route <目的>`，找互相指向的两台设备。
11. **配置变更前先备份路由表**：`show ip route` 与 `show running-config | include ip route` 存档，回滚时有对照。
12. **用 ping 指定源地址验证回程**：`ping 198.51.100.5 source 192.0.2.10` 能暴露回程路由缺失，普通 ping 无法发现。

## 八、常见陷阱清单

| # | 现象 | 根因 | 排查 / 规避 |
|---|------|------|-------------|
| 1 | 配了静态路由仍不通 | 存在更长前缀的路由把静态挤掉 | `show ip route <目的>` 看实际命中的是哪一条 |
| 2 | 路由表里有条目但不转发 | 没有 `>` 标志，未下刷 FIB | 检查下一跳是否可达 / 是否递归失败 |
| 3 | 接口 up/down 直连路由消失 | 协议层未 up（协商、封装、认证问题） | 查接口状态与链路层协商 |
| 4 | 主链路断了备份没起来 | 浮动静态 AD 配得与主路由相同 → 变成等价路由 | 备份 AD 设为主路由 +10 以上 |
| 5 | 去程通、回程断（单通） | 只有单端配了路由或浮动静态 | 双向对称配置，用带 source 的 ping 验证 |
| 6 | 默认路由指向的出口挂了全网不通 | 核心设备也配了默认路由 | 核心只保留明细/汇总，默认路由只放末梢 |
| 7 | 汇总后部分地址不通 | 汇总覆盖了未分配的缺口，形成黑洞 | 配 `null0` 防环，或只宣告明细 |
| 8 | traceroute 中某地址反复出现 | 两台设备下一跳互指形成环路 | 沿路查路由表，找互相指向的两台设备 |
| 9 | 明明路由正确流量却走另一条 | 接口上配了 PBR 且已命中 | `show route-map`、`show ip policy` 检查 |
| 10 | 同一条 TCP 会话达不到聚合带宽 | 等价路由按流哈希，单会话固定一条路径 | 属正常；多会话才能分担，或改 per-packet（不推荐） |
| 11 | 静态路由下一跳不可达被丢弃 | 下一跳不直连且无法递归解析 | 先补一条到下一跳的路由，或改用直连下一跳 |
| 12 | 改了 OSPF 网络里的静态路由不生效 | 华为 OSPF preference 10 < 静态 60 | 调低静态 preference（如 `preference 9`） |
| 13 | `ping` 通但业务不通 | 端口未监听 / ACL 拦截，属 Type 3 Code 3 | 查服务端口，用 `telnet <ip> <port>` 验证 |
| 14 | 环路时网络整体变慢 | 环路流量占满带宽、设备 CPU 升高 | 立即定位并断开一条链路，再修配置 |
| 15 | 设备重启后路由丢失 | 静态路由配在运行配置未保存 | 变更后 `write memory` / `save` |

11. 策略路由 PBR 的执行位置在路由表之前还是之后？说明其匹配顺序与未命中时的行为。

<details>
<summary>参考答案</summary>

1. 匹配 `0.0.0.0/0`、`192.0.2.0/24`、`192.0.2.0/25`、`192.0.2.64/26` 共 4 条。第 1 步取最长前缀：`/26` 最长，全胜。第 2 步无需比 AD（只有一条 /26）。**命中 `192.0.2.64/26`（OSPF AD 110）**。注意直连的 `/24` 与静态的 `/25` 都因前缀更短被淘汰——具体优先压过可信度优先。

2. 四个 /24 连续且起点按 /22 对齐（第三字节 0 能被 4 整除）：合并后前缀长度 `24 − log2(4) = 24 − 2 = 22`，即 **`192.0.0.0/22`**，点分掩码 `255.255.252.0`，覆盖 `192.0.0.0 ~ 192.0.3.255`。配置：`ip route 192.0.0.0 255.255.252.0 203.0.113.2`。明细由 4 条降为 1 条。

3. 初始 TTL=128，每跳减 1，减到 0 的那一跳丢弃。递减次数 = 128，所以报文在**第 128 跳**被丢弃，回 ICMP Time Exceeded（Type 11, Code 0）。

4. 前缀长度相同（都是 /24），比 AD：AD 1 < 20，所以 **AD 1 的那条进 FIB**。把 AD 1 那条的下一跳接口 shutdown 后，其下一跳不可达被撤销，**AD 20 的备份装入 FIB**（这就是浮动静态）。

5. **不能生效**。静态路由的下一跳必须可达：要么直连，要么能通过递归查询找到一条到该下一跳的路由。本例没有任何能到达 `203.0.113.1` 的路由，递归失败，该静态路由不装入 FIB。

6. 排查顺序：① 确认 PC 能到服务器的路径（`traceroute`）；② 在 PC 上 `ping <服务器> source <PC 的 IP>` 验证；③ 在服务器上 `traceroute <PC>` 看回程在哪一跳断；④ 逐跳查中间设备是否有到 PC 网段的路由（`show ip route <PC 网段>`）；⑤ 查是否只配了单向静态路由；⑥ 查反向路径 ACL / uRPF 是否丢弃。最可能是**回程路由缺失或不对称**。

7. 说明存在**路由环路**：两台设备互相把去往某目的网段的下一跳指向对方。定位方法：沿 traceroute 的输出顺序，在每台设备上执行 `show ip route <目的网段>`，找到两条互为下一跳的路由（如 R1 指向 R2、R2 指向 R1），修正其中一条即可。

8. 因为最长前缀匹配**先比前缀长度，再比 AD**。直连路由虽然 AD=0 最可信，但它的前缀通常是 /24；一旦存在 /25、/26 等更长前缀的静态/动态路由，前缀更具体者直接胜出，AD 根本没机会参与比较。这是「路由表里直连在，流量却走别处」的根本原因。

9. 触发条件：主路由的**下一跳变为不可达**（通常是承载它的直连链路/接口 down），此时主路由被撤销，AD 更大的浮动静态装入 FIB；主路由恢复后自动抢占回来。无法覆盖的场景：远端设备本身故障、或链路仍 up 而故障在其下游——此时下一跳依然可达，路由不会切换，必须靠 BFD 或动态路由感知。

10. 度量（Metric）解决「**同一协议内部**多条路径谁更优」，各协议定义不同（OSPF 用 Cost、RIP 用跳数）；管理距离（AD）解决「**不同协议之间**同前缀长度时该信谁」，是厂商定义的全局优先级。需要两个指标是因为同一协议内部的度量与其它协议不可比，必须有一层跨协议的裁决标准。

11. PBR 在**路由表之前**执行：报文进入接口后先检查是否有 `ip policy route-map`，命中就按 `set` 转发并完全绕过路由表。匹配顺序为 route-map 序号从小到大，**第一条命中即生效**；所有条目都未命中时，报文回退到正常路由表查表（对路由策略类 route-map 则是隐式 deny）。

12. 汇总路由覆盖的地址块里若存在未分配或不存在的网段，宣告汇总后发往这些地址的流量会被吸引过来，到达本网后无明细路由可匹配，最终被丢弃——这就是黑洞。null0 防环路由用**与汇总完全相同的同前缀**指向 null0 接口：匹配到汇总但没有更长明细的流量会被 null0 立即丢弃（并回 ICMP 不可达），而不是被默认路由或更短前缀的路由送回上游形成环路。

</details>
