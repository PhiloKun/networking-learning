# 第 07 章 · IPv6 与过渡技术

> **一句话定位**：把 IPv6 从「地址太长记不住」变成可规划的工程对象——掌握 128 位编址、NDP 取代 ARP 的机制、SLAAC 与 DHCPv6 的分工、以及双栈/隧道/翻译三类过渡技术的取舍，读完能给一个园区做完整的 IPv6 编址与迁移方案。
> **前置知识**：第 06 章 IPv4 地址与子网划分 ｜ **难度**：★★★ ｜ **建议投入**：150 分钟

## 一、学习目标

1. 能对任意 IPv6 地址完成压缩、展开与合法性校验，并说出 `::` 只能出现一次的数学原因。
2. 能按前缀区分 GUA / ULA / 链路本地 / 组播 / 环回 / 未指定，并算出任意地址的请求节点组播。
3. 能逐字段解释 40 字节 IPv6 固定首部，并说明扩展首部链的顺序与用途。
4. 能复述 NDP 的 RS/RA/NS/NA 四种报文与 SLAAC 的地址生成全过程（含 EUI-64 与隐私扩展）。
5. 能根据 `M`/`O` 标志判断主机该用 SLAAC 还是 DHCPv6 获取地址与 DNS。
6. 能对比双栈、隧道（6to4/ISATAP/DS-Lite）、翻译（NAT64/464XLAT）的封装开销与适用场景。

## 二、核心概念总览

```
        IPv6 地址 = 128 bit = 前 64 位「前缀」 + 后 64 位「接口标识 IID」
   ├───────────────────── 前缀 /64 ─────────────────────┼──────── IID 64 bit ────────┤
   │ 2001:0db8:abcd:0100                               │ 021a:2bff:fe3c:4d5e        │
   │ └ 全局路由 /48 ┘└站点 /56┘└网段 ┘                  │ ← EUI-64 或随机(隐私扩展)   │
   └───────────────────────────────────────────────────┴────────────────────────────┘
                                     │
     ┌───────────────┬───────────────┼───────────────┬────────────────┐
     ▼               ▼               ▼               ▼                ▼
 ┌────────┐    ┌──────────┐   ┌───────────┐  ┌────────────┐  ┌──────────────┐
 │ 地址类型 │    │  NDP     │   │  SLAAC    │  │ DHCPv6     │  │  过渡技术     │
 │ GUA/ULA │    │ 取代 ARP │   │ 无状态配置 │  │ 有状态配置  │  │ 双栈/隧道/翻译 │
 │ LLA/组播│    │NS/NA/RS/RA│  │ EUI-64+隐私│  │ M/O 标志决定│  │ 6to4/NAT64   │
 └────────┘    └──────────┘   └───────────┘  └────────────┘  └──────────────┘
```

上图把 IPv6 的骨架拆成五块：**编址**（前缀 + IID 的二分法决定了后面一切）、**地址类型**（不同前缀承担不同职责）、**NDP**（用 ICMPv6 取代了 ARP 的全部功能）、**地址自动配置**（SLAAC 与 DHCPv6 两条路线由 RA 标志决定）、**过渡**（IPv4 与 IPv6 长期共存的手段）。与 IPv4 最大的差别是：IPv6 **没有广播**，所有「一对多」都改用组播与任播；**没有 ARP**，改用 NDP；**网段固定 /64**，因为 SLAAC 要求接口标识正好 64 位。

## 三、机制详解

### 3.1 128 位地址与冒号十六进制表示

IPv6 地址写成 8 组、每组 16 位十六进制，用 `:` 分隔：`2001:0db8:0000:0000:0000:0000:0000:0001`。

**RFC 5952 的三条压缩规则**：

1. 每组去掉前导零，但至少保留一位（`0000` 写成 `0`，不写成空）。
2. 最长的一段**连续零组**用 `::` 代替，且长度必须 ≥ 2 组（单个零组不能压缩）。
3. 有多段等长时只压缩**最靠左**的那一段；全零地址写作 `::`。

```
2001:0db8:0000:0000:0000:0000:0000:0001  →  2001:db8::1
fe80:0000:0000:0000:0200:00ff:fe00:000a  →  fe80::200:ff:fe00:a
0000:0000:0000:0000:0000:0000:0000:0001  →  ::1
2001:0db8:0001:0002:0003:0004:0005:0006  →  2001:db8:1:2:3:4:5:6   （无可压缩段）
```

**`::` 为什么只能出现一次**：`::` 表示「这里补若干个全零组」，但补几个是由总组数 8 减去已写出的组数算出来的。若出现两次，两个 `::` 各自该补多少就无解，地址歧义，直接判非法。前缀长度写作 `地址/前缀`，如 `2001:db8:abcd::/48`。

### 3.2 地址类型：前缀决定职责

| 类型 | 前缀 | 作用 | IPv4 对应物 |
|---|---|---|---|
| 全球单播 GUA | `2000::/3` | 公网可路由（2000:: ~ 3fff:…） | 公网地址 |
| 唯一本地 ULA | `fc00::/7` | 私网用途（常用 `fd00::/8` + 40 位随机全局 ID） | RFC 1918 私网 |
| 链路本地 LLA | `fe80::/10` | 每接口自动生成，仅本链路有效 | 169.254/16（但用途更广） |
| 组播 | `ff00::/8` | 一对多，取代 IPv4 广播 | 224.0.0.0/4 |
| 环回 | `::1/128` | 本机协议栈 | 127.0.0.1 |
| 未指定 | `::/128` | 仅作源地址（DAD/SLAAC 时） | 0.0.0.0 |
| IPv4 映射 | `::ffff:0:0/96` | 双栈 socket 表示 IPv4 对端 | — |
| NAT64 前缀 | `64:ff9b::/96` | RFC 6052 翻译前缀 | — |
| 文档专用 | `2001:db8::/32` | RFC 3849，本仓库统一教学前缀 | 192.0.2.0/24 |

**关键工程差异**：① 每台启用 IPv6 的主机**每个接口都有一个 fe80:: 链路本地地址**，路由器之间靠它建立邻居，因此 `ping6 fe80::1` 必须带接口（Linux 写 `%eth0`，Windows 写 `%12`）；② ULA 不等于「不能上网」，它只是不可在公网路由，配合 NAT66 才能出网，多数企业选择直接用 GUA 而非 ULA。

### 3.3 组播与请求节点组播

IPv6 没有广播，`ff00::/8` 承担了全部「一对多」职责。组地址的第二个 16 位里含**标志**（4 位）与**范围**（4 位）：范围 `1`=接口本地、`2`=链路本地、`5`=站点本地、`e`=全球。

| 组播地址 | 含义 |
|---|---|
| `ff02::1` | 链路本地范围的所有节点（等价于「广播」） |
| `ff02::2` | 链路本地范围的所有路由器（RS 报文发到这里） |
| `ff02::1:ff00:0/104` | **请求节点组播**（Solicited-Node Multicast）前缀 |
| `ff02::5` / `ff02::6` | OSPFv3 的 AllSPFRouters / AllDRouters |
| `ff02::9` | RIPng |
| `ff02::a` | EIGRP for IPv6 |

**请求节点组播 = `ff02::1:ff00:0/104` + 目标地址低 24 位**。以 `2001:db8::1` 为例：

```
低 24 位 = 0x000001
请求节点组播 = ff02::1:ff00:1
```

因为只取 24 位，同一 /104 内的多个地址会映射到同一组播组（存在重叠），但配合链路上「谁被问谁应答」的机制，实际不会出错。NDP 的 NS 就发给它，避免惊动整条链路。

### 3.4 IPv6 首部与扩展首部链

IPv6 把首部简化为**固定 40 字节**，去掉了校验和、可选字段全挪到扩展首部（字段详解见第五节）。设计动机有三条：

1. **固定长度**：路由器无需像 IPv4 那样读 IHL 再定位，硬件转发更快。
2. **取消首部校验和**：链路层与传输层已有校验，重复校验收益低；且 TTL 每跳变化导致 IPv4 必须每跳重算校验和，取消后省一次运算。
3. **取消分片（路由器侧）**：IPv6 要求路径上所有链路 MTU ≥ 1280，路由器不再分片，想分片只能由源主机自己用分片扩展首部完成——这直接催生了 PMTUD 的重要性。

**扩展首部链**按固定顺序串在固定首部之后，用 `下一首部` 字段串联：

```
Hop-by-Hop(0) → 目的地选项(60) → 路由(43) → 分片(44) → AH(51) → ESP(50) → 目的地选项(60) → 上层(6/17/58)
```

常见取值：`0` 逐跳选项、`43` 路由、`44` 分片、`50` ESP、`51` AH、`58` ICMPv6、`59` 无下一首部、`6` TCP、`17` UDP。**逐跳选项必须紧跟在固定首部之后**，其余可以任意顺序（但实际实现要求按上表顺序），中间设备只需处理逐跳选项，其余交给端主机。

### 3.5 NDP：ICMPv6 取代 ARP

NDP（Neighbor Discovery Protocol，邻居发现协议）用 5 种 ICMPv6 报文完成 IPv4 里 ARP + ICMP 重定向 + 部分 DHCP 的功能：

| 报文 | 类型 | 目的地址 | 作用 |
|---|---|---|---|
| RS Router Solicitation | 133 | `ff02::2` | 主机刚上线，催路由器马上发 RA |
| RA Router Advertisement | 134 | `ff02::1` | 路由器周期（默认 200s）宣告前缀、网关、M/O 标志 |
| NS Neighbor Solicitation | 135 | 请求节点组播 | 解析邻居 MAC / 做 DAD |
| NA Neighbor Advertisement | 136 | 单播或 `ff02::1` | 应答 NS，携带自己的 MAC |
| Redirect | 137 | 单播 | 告诉主机有更优的下一跳 |

**NS/NA 与 ARP 的对应关系**：ARP 是「广播问、单播答」，NS/NA 是「组播问（只发给请求节点组播）、单播答」。由于只发给目标所属的组播组，链路上大多数主机根本不会被打扰，比 ARP 高效得多。

**DAD（重复地址检测）**：地址正式启用前，主机把该地址的请求节点组播作为目的，源地址用 `::`（未指定）发一条 NS。若收到任何 NA，说明地址冲突，该地址被标记为 `duplicate` 并不可用。`ping` 一个候选地址返回「重复」就是 DAD 失败。

### 3.6 SLAAC 与 DHCPv6 的分工

**SLAAC（无状态地址自动配置）**流程：

1. 主机生成 `fe80::/64` 链路本地地址（EUI-64 或随机），先做 DAD。
2. 发 RS 到 `ff02::2`，或等路由器的周期性 RA。
3. RA 携带一个或多个前缀（`A` 标志置位表示可用于 SLAAC）+ 默认网关（RA 源地址）+ 生命周期。
4. 主机把「前缀 + 自己的 64 位 IID」拼成 GUA，再做一次 DAD，通过后启用。
5. DNS 等信息要另外从 RA 的 RDNSS 选项或 DHCPv6 获取。

**RA 的两个关键标志**：

| 标志 | 含义 | 主机行为 |
|---|---|---|
| `M` Managed | 地址由 DHCPv6 管理 | M=1 时主机用 DHCPv6 拿地址（SLAAC 地址通常不再自动生成） |
| `O` Other | 其它配置由 DHCPv6 提供 | O=1 时主机用 DHCPv6 拿 DNS、域名等 |

四种典型组合：M=0/O=0 纯 SLAAC；M=0/O=1 SLAAC 出地址 + DHCPv6 出 DNS（**企业网最常见**）；M=1/O=1 全 DHCPv6；M=1/O=0 少见。

**EUI-64 接口标识**：把 48 位 MAC 从中间劈开插入 `FF:FE`，再把首字节第 7 位（U/L 位，掩码 0x02）取反。取反的原因（RFC 4291 附录 A）是 MAC 与该位在两种语境下取值约定相反，取反后语义一致、也能区分「硬件派生」与「本地分配」。**隐私扩展（RFC 4941）**则用 64 位随机数代替 MAC 派生，临时地址 preferred 7 天、valid 14 天，代价是地址与资产不再一一对应。

### 3.7 过渡技术：并行 / 封装 / 翻译三类

| 技术 | 类别 | 封装 / 转换方式 | 外层 | 额外开销 | 适用场景 |
|---|---|---|---|---|---|
| 双栈 Dual Stack | 并行 | 不封装，两套协议栈并行 | 无 | 0 字节 | 新建网络、终端就绪 |
| 手工隧道（GRE/IP6IP） | 封装 | IPv6 装进 IPv4 | 协议号 41 / 47 | +20 / +24 | 点对点固定互联 |
| 6to4 | 封装 | IPv6 装进 IPv4，地址 `2002::/16` 内嵌 IPv4 | 协议号 41 | +20 | 历史方案，已弃用 |
| ISATAP | 封装 | 站内隧道，接口标识 `::5EFE:a.b.c.d` | 协议号 41 | +20 | 企业内网渐进引入 |
| Teredo | 封装 | IPv6-in-UDP-in-IPv4，可穿 NAT | UDP/3544 | +28 | NAT 后主机访问 IPv6 |
| NAT64 + DNS64 | 翻译 | 头部翻译，前缀 `64:ff9b::/96` | 无（翻译） | 0 | IPv6-only 访问 IPv4 |
| DS-Lite | 封装 | IPv4 装进 IPv6（软线） | 协议号 4 | +40 | 运营商承载海量 IPv4 接入 |
| 464XLAT | 翻译 | 终端 CLAT 无状态 + 网络 PLAT 有状态 | 两次翻译 | 0 | IPv6-only 移动网络 |

**隧道必然吃 MTU**：物理链路 1500 字节时，6to4 内层 IPv6 MTU 只剩 1480，TCP MSS 建议降到 1420；DS-Lite 内层 IPv4 MTU 只剩 1460，MSS 1420。不调整就会出现「ping 通、小包通、大包卡死」的 MTU 黑洞（第 18 章详述）。

**安全考虑**：RA 没有任何认证，伪造 RA 可以把自己变成全链路的默认网关。**RA Guard** 让接入交换机丢弃来自非信任端口的 RA；**SEND**（Secure Neighbor Discovery）用密码学签名保护 NDP，但部署率低，工程上仍以 RA Guard + 端口安全为主。

## 四、动手验证

**1) `ipv6_format.py` → 压缩/展开/校验/类型识别**

```
输入           : 2001:db8:abcd:0012:0000:0000:0000:0001
规范压缩形式   : 2001:db8:abcd:12::1
完整展开形式   : 2001:0db8:abcd:0012:0000:0000:0000:0001
类型           : 文档专用 Documentation  [匹配 2001:db8::/32]
请求节点组播   : ff02::1:ff00:1   （NDP 的 NS 报文就发给它）
低 24 位       : 000001   （请求节点组播只取这 24 位）
```

脚本内置 10 条合法用例（含「全零」「单零组不压缩」「8 组全非零不压缩」等边界）与 6 条非法用例（`::` 两次、组数不足、三个冒号、非法字符、越界前缀），压缩结果逐条与标准库断言一致。

**2) `ipv6_subnet.py` → /48 → /56 → /64 三层规划**

```
  │ 全局路由前缀 48 bit │ 站点 8 bit │ 网段 8 bit │ 接口标识 64 bit │
  /48 → /64：2^(64−48) = 2^16 = 65536 个 /64 网段
总部大楼      2001:db8:abcd::/56        办公区         10    2001:db8:abcd::/64
总部大楼      2001:db8:abcd::/56        无线访客       40    2001:db8:abcd:a::/64
研发园区      2001:db8:abcd:100::/56    测试环境       50    2001:db8:abcd:101::/64
```

**结论**：一个 /48 提供 2^16 = 65536 个 /64，足以支撑「256 站点 × 每站点 256 网段」；网段前缀必须固定 /64 才能让 SLAAC 工作。

**3) `eui64_gen.py` → MAC 生成 EUI-64**

```
步骤 1：02-00-00-00-00-0A  →  02-00-00-ff-fe-00-00-0a
步骤 2：02 XOR 02 = 00  →  00-00-00-ff-fe-00-00-0a
步骤 3：接口标识 IID = 0000:00ff:fe00:000a
链路本地地址   : fe80::ff:fe00:a
全球单播地址   : 2001:db8:abcd:100:0:ff:fe00:a
```

**结论**：EUI-64 完全确定（同一 MAC 永远得到同一 IID）；脚本同时给出 3 个隐私扩展随机 IID 作对比。

**4) `transition_demo.py` → 过渡技术与封装开销**

```
6to4 / ISATAP（IPv6-in-IPv4）  内层可用 MTU = 1500 − 20 = 1480  → TCP MSS 建议 1420（内层 IP 头 40）
DS-Lite（IPv4-in-IPv6）        内层可用 MTU = 1500 − 40 = 1460  → TCP MSS 建议 1420（内层 IP 头 20）
```

**结论**：隧道开销必须与 MTU/MSS 规划同时做，否则大包会被黑洞丢弃。

## 五、关键字段 / 报文格式解剖

**IPv6 固定首部（40 字节）**

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| 版本 Version | 4 bit | 协议版本 | 6 |
| 流量类别 Traffic Class | 8 bit | 区分服务（高 6 位 DSCP + 低 2 位 ECN） | 0；语音 EF = 0xB8 |
| 流标签 Flow Label | 20 bit | 标识同一「流」，供中间设备做流级处理 | 0（默认，未使用） |
| 载荷长度 Payload Length | 16 bit | **不含首部**的字节数 | 与 IPv4「总长度」口径不同 |
| 下一首部 Next Header | 8 bit | 上层协议或下一个扩展首部 | 6 TCP、17 UDP、58 ICMPv6、43 路由、44 分片、59 无 |
| 跳数限制 Hop Limit | 8 bit | 每跳减 1，为 0 丢弃 | 初始 64（Linux）/ 128（Windows）/ 255（网络设备） |
| 源地址 Source Address | 128 bit | 发送方 | — |
| 目的地址 Destination Address | 128 bit | 接收方 | — |

**ICMPv6 常用类型**

| 类型 | 名称 | 用途 |
|---|---|---|
| 1 | Destination Unreachable | 目的不可达 |
| 2 | Packet Too Big | **PMTUD 的核心**，携带可用 MTU |
| 3 | Time Exceeded | 跳数超限，traceroute 依赖它 |
| 4 | Parameter Problem | 首部参数错误 |
| 128 / 129 | Echo Request / Reply | `ping6` |
| 133 / 134 | RS / RA | 路由器发现与 SLAAC |
| 135 / 136 | NS / NA | 地址解析（取代 ARP） |
| 137 | Redirect | 更优下一跳 |

**RA 报文关键字段**

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| Cur Hop Limit | 8 bit | 告诉主机 IP 首部该填的跳数 | 64 |
| M / O 标志 | 1+1 bit | 地址/其它配置是否用 DHCPv6 | 企业网常 0/1 |
| Router Lifetime | 16 bit | 该 RA 作为默认网关的有效期（秒） | 1800；为 0 表示不是默认网关 |
| Reachable Time | 32 bit | 邻居可达判定时间 | 30000 ms |
| Retrans Timer | 32 bit | 重传间隔（DAD 也用它） | 1000 ms |
| 前缀选项 · Prefix | 128 bit | 可在 SLAAC 使用的前缀 | /64 |
| 前缀选项 · Valid/Preferred Lifetime | 32+32 bit | 地址有效期与首选期（秒） | 2592000 / 604800 |
| 前缀选项 · A / L 标志 | 1+1 bit | 是否可 SLAAC / 是否链路在线 | A=1, L=1 |

## 六、易混概念对比

| 概念 A | 概念 B | 核心区别 | 典型场景 |
|---|---|---|---|
| GUA | ULA | GUA 在 2000::/3 全网可路由，ULA 在 fc00::/7 仅私网 | 公网接入 vs 内网隔离 |
| 链路本地 LLA | 站点本地 | LLA 仅单条链路有效（fe80::/10），ULA 可跨网段路由 | 邻居发现 vs 私网互联 |
| SLAAC | DHCPv6 | 前者无状态：前缀来自 RA、IID 自己算；后者有状态：服务器分配并记录租期 | M=0 vs M=1 |
| NS/NA | ARP | NS 用组播（请求节点组播）、ARP 用广播；NA 单播应答 | 两者都是地址解析 |
| 请求节点组播 | 全节点组播 | 前者 ff02::1:ff00:0/104 只通知相关主机，后者 ff02::1 通知全链路 | NDP 精确寻址 vs DAD/RA 广播式 |
| 双栈 | 隧道 | 双栈两套协议栈并行不封装；隧道把一种包装进另一种 | 新建网络 vs 穿越旧网络 |
| NAT64 | DS-Lite | NAT64 做地址翻译（改地址不改封装），DS-Lite 做封装（不改地址） | IPv6-only 访问 IPv4 vs 运营商承载 IPv4 |

## 七、工程实践与最佳实践

1. **网段一律用 /64**：SLAAC 规定接口标识 64 位，切成 /80 或 /96 会让终端自动配置失效，这不是「浪费」而是「标准要求」。
2. **按 /48 给站点、/56 给楼栋、/64 给网段做三层规划**：位段固定才能让汇聚层用一条前缀聚合，位段乱放会导致路由表无法压缩。
3. **不要用 ULA 替代 GUA 做主干**：ULA 不可公网路由，一旦需要直连互联网或云服务就要再做一次 NAT66，徒增复杂度。
4. **RA Guard + 端口安全必须开**：伪造 RA 能瞬间劫持全链路默认网关，这是 IPv6 接入网最高频的攻击面。
5. **RA 的 M/O 标志按企业策略统一**：想用 DNS 下发就用 O=1；要审计每个地址就用 M=1 全 DHCPv6，混用会导致部分终端拿不到 DNS。
6. **路由器上不要下发放置 `::/0` 的 RA**：Router Lifetime 设为 0 表示「只发前缀不发默认网关」，避免把不该做网关的设备变成出口。
7. **ICMPv6 不能一刀切禁掉**：类型 2（Packet Too Big）被禁会导致 PMTUD 失效、大包黑洞；类型 135/136 被禁则邻居解析直接失败。ACL 里要放行必要类型。
8. **隧道部署必须同步调 MTU/MSS**：把隧道接口 MTU 设为 `1500 − 封装开销`，并在两端做 TCP MSS 钳制，否则表现为「小包通、大包死」。
9. **DAD 失败要当故障处理**：地址标记 duplicate 意味着有人手工配了同地址或存在欺骗，必须立即定位而非忽略。
10. **双栈上线前先测 IPv6 优先行为**：RFC 6724 规定主机优先 IPv6，若 IPv6 路径质量差会出现「打开网页先等超时再回落 IPv4」的体验问题。
11. **监控要同时看 IPv4 与 IPv6 流量**：很多监控只统计 IPv4，双栈上线后 IPv6 流量成为盲区。
12. **过渡技术选型优先「双栈 → NAT64 → 隧道」**：双栈最稳，NAT64 次之（需 DNS64 配合），隧道（尤其是 6to4/Teredo）问题最多，新项目不应再选。

## 八、常见陷阱清单

| # | 现象 | 根因 | 排查 / 规避 |
|---|------|------|-------------|
| 1 | `ping6 fe80::1` 报 no route | 链路本地地址必须指定出接口 | Linux `ping6 fe80::1%eth0`，Windows `ping -6 fe80::1%12` |
| 2 | 地址写成 `2001:db8::1::2` 被拒 | `::` 出现两次造成歧义 | 一个地址中 `::` 只能出现一次 |
| 3 | 把 /56 当成「可用主机 2^56」 | 混淆「地址数」与「可用网段数」 | /56 是网段划分位，接口标识另有 64 位 |
| 4 | 终端只拿到 fe80，没有 GUA | RA 未下发前缀或 A 标志为 0 | 查 RA 前缀选项的 A/L 标志与生命周期 |
| 5 | 部分终端没有 DNS | RA 只发了地址、没发 RDNSS，且 O 标志为 0 | 开 O=1 用 DHCPv6 下发，或 RA 里加 RDNSS |
| 6 | 改完地址后旧地址还在 | 隐私扩展保留多个地址、生命周期未到 | 属正常；用 `ip -6 addr` 看 valid/preferred 时间 |
| 7 | 大包不通、小包通 | 隧道或中间链路 MTU 小于 1500 | 查 `ip link` 的 MTU，看是否收到 ICMPv6 type 2 |
| 8 | 邻居解析失败、ping 不通同网段 | ICMPv6 135/136 被 ACL 拦 | 放行 ICMPv6 NS/NA，别一刀切禁 ICMPv6 |
| 9 | 地址显示 duplicate | DAD 检测到冲突 | 找出手工配置或做欺骗的主机，及时清理 |
| 10 | 手工配的 /64 前缀与网关不同网段 | 前缀算错，网关不在本链路 | 网关必须是本链路内的 LLA 或同 /64 的 GUA |
| 11 | 双栈设备上网变慢 | IPv6 路径不通但系统仍优先试 IPv6 | 修好 IPv6 路径或用 RFC 6724 策略调整优先级 |
| 12 | 6to4 隧道时通时不通 | 依赖公共中继 192.88.99.1，历史方案 | 迁移到双栈或 NAT64，不要继续用 6to4 |
| 13 | DHCPv6 拿不到地址 | 交换机 DHCPv6 中继/Snooping 未放行 | 检查中继与信任口配置 |
| 14 | 路由表出现海量 /64 | 位段规划不对齐，无法聚合 | 重做编址，站点与网段号放在固定位段 |
| 15 | RA 被伪造导致流量被劫持 | 无认证的 RA | 接入交换机开 RA Guard，只信任上行口 |

<details>
<summary>参考答案</summary>

1. 压缩：`2001:db8::ff00:42:8329`。展开形式：`2001:0db8:0000:0000:0000:ff00:0042:8329`（8 组，中间 3 组为 0 用 `::` 代替，且是最长零段）。

2. 步骤：① 中间插 FF:FE → `00-1a-2b-ff-fe-3c-4d-5e`；② 首字节 `00 XOR 02 = 02` → `02-1a-2b-ff-fe-3c-4d-5e`；③ IID = `021a:2bff:fe3c:4d5e`。链路本地 = `fe80::` + IID = **`fe80::21a:2bff:fe3c:4d5e`**。

3. 取地址低 24 位：`fe80::200:ff:fe00:a` 的低 24 位来自最后一段 `00:000a` → `0x00000a`。请求节点组播 = `ff02::1:ff` + 低 24 位 = **`ff02::1:ff00:a`**。

4. `/48 → /56`：`2^(56−48) = 256` 个；`/48 → /64`：`2^(64−48) = 65536` 个；每个 `/56` 内 `/64` 数量：`2^(64−56) = 256` 个。

5. 6to4 封装开销 20 字节（外层 IPv4）：内层 IPv6 MTU = `1500 − 20 = 1480`；TCP MSS = `1480 − 40(IPv6头) − 20(TCP头) = 1420`。DS-Lite 外层是 IPv6（40 字节）：内层 IPv4 MTU = `1500 − 40 = 1460`；TCP MSS = `1460 − 20(IPv4头) − 20(TCP头) = 1420`。

6. Valid Lifetime `2592000 ÷ 86400 = 30` 天；Preferred Lifetime `604800 ÷ 86400 = 7` 天。关系：**Preferred ≤ Valid**。地址在 Preferred 期内可正常使用；超过 Preferred 进入「已弃用」状态，仍可接收连接但不再用于新连接；超过 Valid 后地址彻底失效。

7. ① 确认接口 IPv6 是否启用（`sysctl net.ipv6.conf.eth0.disable_ipv6`）；② 抓 RA（`tcpdump -i eth0 icmp6 and ip6[40]==134`）看是否收到、前缀选项 A 标志是否为 1；③ 查是否有路由器下发前缀（`ip -6 route` 看是否有 `ra` 来源的路由）；④ 查是否有 RA Guard/防火墙拦 ICMPv6；⑤ 若 M=1 则查 DHCPv6 是否正常。

8. 最可能是 **MTU 黑洞**（PMTUD 失效）：路径中某段 MTU 小于 1500、DF 位导致大包被丢、而返回的 ICMPv6 type 2 被防火墙拦截。验证：`ping6 -s 1452 -M do <目标>` 观察是否卡住；`traceroute6` 看哪一跳开始失败；抓包确认是否收到 Packet Too Big。

9. `::` 表示「此处补若干全零组」，补几个由总组数 8 减去已写组的数量决定。若出现两次，两次各补多少就没有唯一解，地址产生歧义，因此规定只能出现一次（写两次直接判非法）。

10. M（Managed）=1 表示地址由 DHCPv6 分配；O（Other）=1 表示 DNS、域名等其它配置由 DHCPv6 提供。企业网最常见组合是 **M=0 / O=1**：地址用 SLAAC 自动生成，DNS 等参数由 DHCPv6 下发（也可用 RA 的 RDNSS 选项替代）。

11. ① NS 发给请求节点组播而非广播，链路上只有目标及其相关主机处理，效率更高、打扰更少；② NA 单播应答，进一步减少无关流量；③ NDP 还能携带选项（如源链路层地址、MTU、前缀），并内置 DAD 机制，ARP 不具备；④ 组播寻址天然支持扩展（如 SEND 加签名）。

12. 双栈：两套协议栈并行，最稳、开销为 0，适合新建网络与终端就绪的环境，风险是需要双份运维（ACL/QoS）；NAT64：做地址翻译，让 IPv6-only 网络访问 IPv4 互联网，需 DNS64 配合，风险是协议不支持翻译（内嵌 IPv4 地址）时会失败；6to4：把 IPv6 装进 IPv4 通过公网隧道，适合早期「有公网 IPv4 想接 IPv6」，风险是依赖公共中继 192.88.99.1、NAT 后不可用，已被业界弃用。

</details>
