# 第 06 章 · IPv4 地址与子网划分

> **一句话定位**：把 IPv4 地址从「一串数字」变成可精确计算的地址块——会算网络号/广播/主机范围，会用 VLSM 做地址规划，会用 CIDR 做路由聚合，会解释 ARP 与 IP 首部每一个字段，读完能独立完成一份不浪费地址的企业 IP 规划书。
> **前置知识**：第 04 章 以太网与交换技术、第 05 章 WLAN（广播域概念） ｜ **难度**：★★☆ ｜ **建议投入**：150 分钟

## 一、学习目标

1. 能熟练完成点分十进制与 32 位二进制互转，并说出 A/B/C/D/E 五类地址的首位特征与默认掩码。
2. 能由 `IP/前缀` 在 30 秒内算出网络地址、广播地址、可用主机范围、可用主机数、通配符掩码。
3. 能按需求降序完成 VLSM 划分，并说明为什么必须「先大后小」。
4. 能将一组连续网段聚合成最少的 CIDR 前缀，并解释聚合为什么会造成路由黑洞。
5. 能复述 ARP 的「广播请求 / 单播应答 / 缓存老化 / 免费 ARP」四个环节，并说清 ARP 欺骗的成因与 DAI 防御原理。
6. 能逐字段解释 IPv4 首部 20 字节固定部分，指出每个字段的比特位与常见取值。

```

   ┌──────────────────────────── 前缀长度决定分界线 ────────────────────────────┐
   │  192   .   0    .   2    .  130      /26 → 网络 26 位 | 主机 6 位          │
   │ 11000000 00000000 00000010 10000010                                     │
   │ └────────────── 网络位 26 ──────────────┘└ 主机位 6 ┘                    │
   └─────────────────────────────────────────────────────────────────────────┘
                                     │
        ┌────────────────────────────┼────────────────────────────┐
        ▼                            ▼                            ▼
  ┌───────────┐              ┌─────────────┐              ┌──────────────┐
  │ 子网划分   │              │  VLSM       │              │  CIDR 聚合   │
  │ 等长切分   │              │ 变长切分     │              │ 超网合并     │
  │ /24→4×/26 │              │ 100/50/20/2 │              │ 10 条→3 条   │
  └───────────┘              └─────────────┘              └──────────────┘

                      ┌─────────────────────────────────┐
                      │ 二层如何找到你？—— ARP           │
                      │ 广播问「谁是 192.0.2.2」          │

                      │ 缓存老化 300s / 强制刷新用免费 ARP│
```

图中左侧三块是**地址运算**：等长子网划分（Subnetting）把大网按固定长度切开，VLSM（Variable Length Subnet Mask，变长子网掩码）按业务需求切成长度不一的块，CIDR（Classless Inter-Domain Routing，无类域间路由）反过来把连续块合并成一条路由。底下那块是**地址落地的最后一公里**：IP 是逻辑地址，真正在以太网上转发要靠 MAC，两者之间由 ARP（Address Resolution Protocol，地址解析协议）牵线。**地址规划一旦出错，后面所有路由、ACL、NAT 都会跟着错**，所以本章的计算必须做到一次算对。

## 三、机制详解

### 3.1 点分十进制与二进制互转

IPv4 地址是 32 位无符号整数，写成 4 个 8 位组（octet）的十进制，中间用 `.` 分隔。每个 8 位组范围 0–255。

```
192.0.2.130  →  192=11000000  0=00000000  2=00000010  130=10000010
二进制转十进制：按 128 64 32 16 8 4 2 1 各位求和
  10000010 = 128 + 2 = 130
```

快速记忆的「位权表」：

| 位 | 8 | 7 | 6 | 5 | 4 | 3 | 2 | 1 |
|---|---|---|---|---|---|---|---|---|
| 权值 | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
| 掩码常见值 | 128 | 192 | 224 | 240 | 248 | 252 | 254 | 255 |

**掩码的十进制值只可能出现这 8 个**（255.255.255.192 合法，255.255.255.200 非法），因为掩码要求「前面全是 1、后面全是 0」。

### 3.3 子网掩码、前缀长度与通配符

- **子网掩码**：32 位，网络部分全 1、主机部分全 0。`255.255.255.192` 对应前缀 **/26**（数 1 的个数 = 24+2 = 26）。
- **前缀长度**：斜杠后的数字，直接表示网络位数。
- **通配符掩码（反掩码）**：`通配符 = 255.255.255.255 − 掩码`，按位取反。掩码 255.255.255.192 → 通配符 `0.0.0.63`。

| 前缀 | 掩码 | 通配符 | 地址数 | 可用主机 | 块大小 |
|---|---|---|---|---|---|
| /24 | 255.255.255.0 | 0.0.0.255 | 256 | 254 | 256 |
| /25 | 255.255.255.128 | 0.0.0.127 | 128 | 126 | 128 |
| /26 | 255.255.255.192 | 0.0.0.63 | 64 | 62 | 64 |
| /27 | 255.255.255.224 | 0.0.0.31 | 32 | 30 | 32 |
| /28 | 255.255.255.240 | 0.0.0.15 | 16 | 14 | 16 |
| /29 | 255.255.255.248 | 0.0.0.7 | 8 | 6 | 8 |
| /30 | 255.255.255.252 | 0.0.0.3 | 4 | 2 | 4 |
| /31 | 255.255.255.254 | 0.0.0.1 | 2 | 2（点对点） | 2 |
| /32 | 255.255.255.255 | 0.0.0.0 | 1 | 1（主机路由） | 1 |

> 注意：ACL 里必须用**通配符**，不是正掩码。`permit 192.0.2.0 0.0.0.63` 匹配 /26；写成 `255.255.255.192` 会变成「只匹配完全等于该 IP 的地址」，因为通配符里 1 表示「不关心这一位」。

### 3.4 网络号 / 广播 / 主机范围的计算三步法

给定 `IP/前缀`：

1. **块大小** `S = 2^(32 − prefix)`。
2. **网络地址** = 把 IP 向下对齐到 `S` 的整数倍（即 `floor(IP / S) × S`）。
3. **广播地址** = 网络地址 + `S` − 1；**可用主机范围** = 网络地址+1 ~ 广播地址−1（/31、/32 例外）。

**例题**：`192.0.2.130/26`

```
S = 2^(32−26) = 2^6 = 64
网络地址 = floor(130 / 64) × 64 = 2 × 64 = 128  →  192.0.2.128
广播地址 = 128 + 64 − 1 = 191                    →  192.0.2.191
可用主机 = 64 − 2 = 62，范围 .129 ~ .190
```

**例题**：`172.20.30.40/22`

```
S = 2^(32−22) = 2^10 = 1024，落在第三字节上（第三、四字节共 16 位，块覆盖 4 个第三字节值）
第三字节块大小 = 1024 / 256 = 4；30 ÷ 4 = 7 → 7×4 = 28
网络地址 = 172.20.28.0，广播地址 = 172.20.31.255
可用主机 = 1024 − 2 = 1022，范围 172.20.28.1 ~ 172.20.31.254
```

### 3.5 VLSM：按需求切，而不是按长度切

VLSM 解决「等长划分浪费地址」的问题。核心公式：一个子网要容纳 `N` 个可用主机，需要的主机位 `h` 满足

```
2^h − 2 ≥ N        →        h = ceil( log2(N + 2) )
子网前缀 = 32 − h
```

**算法步骤**：

1. 把所有需求按**主机数降序**排列。
2. 对每个需求算出 `h` 与子网前缀。
3. 从地址池中取**第一个能装下的空闲块**分配出去（首次适配）。
4. 把该块的剩余部分按 2 的幂对齐切回空闲池。
5. 重复直到分配完，剩余空间作为扩容预留。

**例题**：`192.0.2.0/24` 上依次给研发 100、市场 50、财务 20、互联链路 2 个可用主机。

| 部门 | 需求 | 2^h−2 ≥ 需求 | h | 前缀 | 分配网段 | 可用范围 | 容量 |
|---|---|---|---|---|---|---|---|
| 研发部 | 100 | 2^7−2=126 ≥ 100 | 7 | /25 | 192.0.2.0 | .1 ~ .126 | 126 |
| 市场部 | 50 | 2^6−2=62 ≥ 50 | 6 | /26 | 192.0.2.128 | .129 ~ .190 | 62 |
| 财务部 | 20 | 2^5−2=30 ≥ 20 | 5 | /27 | 192.0.2.192 | .193 ~ .222 | 30 |
| 互联链路 | 2 | 2^2−2=2 ≥ 2 | 2 | /30 | 192.0.2.224 | .225 ~ .226 | 2 |

剩余 `192.0.2.228/30`、`.232/29`、`.240/28` 共 28 个地址留作扩容。已分配 228/256（89.1%），按需利用率 172/228 = 75.4%。

**为什么必须降序**：若先给「2 个主机」的需求分一个 /30 在 `192.0.2.0/30`，那么连续的 100 主机需求就只能拿到被切碎的 `192.0.2.4` 之后、且找不到对齐的 /25，最终分配失败或产生大量空洞。降序保证大块先占对齐位置。

### 3.6 CIDR 与路由聚合（超网）

CIDR 用「前缀长度」取代了分类地址，让 `192.0.2.0/23` 这种跨 B 类边界的写法合法。**聚合**是把多条明细路由合并成一条更短前缀（超网）的过程：

**合并条件**（必须同时满足）：

1. 两条路由前缀长度相同 `p`；
2. 网络地址相差恰好 `2^(32−p)`（即同一父网的左右两半）；
3. 合并后前缀为 `/(p−1)`，覆盖地址数翻倍。

**例题**：把 `192.0.2.0/26 + 192.0.2.64/26 + 192.0.2.128/26 + 192.0.2.192/26` 聚合。

```
192.0.2.0/26 + 192.0.2.64/26     → 192.0.2.0/25     （差 64 = 2^(32−26)）
192.0.2.128/26 + 192.0.2.192/26  → 192.0.2.128/25
192.0.2.0/25 + 192.0.2.128/25    → 192.0.2.0/24     （差 128 = 2^(32−25)）
```

**聚合的代价**：只能覆盖连续且对齐的地址块。若 `203.0.113.0/24` 里只用了前一半，却宣告整条 `203.0.113.0/24`，发往未使用地址的流量会打到本网后被丢弃——这就是**路由黑洞**。规避手段是宣告聚合路由时同时配一条指向 `null0` 的同前缀路由防环，或只宣告真实在用的明细前缀。

### 3.7 ARP：IP 到 MAC 的最后一公里

同一广播域内，主机知道目的 IP 但不知道目的 MAC，靠 ARP 解析：

1. 查本机 ARP 缓存，命中则直接用。
2. 未命中：广播 **ARP Request**，以太网目的地址 `ff:ff:ff:ff:ff:ff`，`target_mac` 填全 0。
3. 广播域内所有主机都收到，逐条比对 `target_ip` 是否是自己；不是则丢弃（但会**被动学习**发送方的 IP↔MAC 映射）。
4. 目标主机**单播**回 **ARP Reply**，`sender_mac` 填自己的 MAC。
5. 发起方写入缓存，老化时间到后清除。网络不通时**先看 ARP**：`arp -a` 显示 `incomplete` 说明二层都没解析成功。

**免费 ARP（Gratuitous ARP）**：主机主动广播「我的 IP 对应我的 MAC」（`sender_ip = target_ip`，`target_mac` 全 0）。两个用途——① 探测 IP 冲突：若有别的主机应答同一 IP，说明地址重复；② 快速刷新：网卡更换、VRRP/HSRP 主备切换、容器漂移后立即让全网更新缓存，不用等老化。

**ARP 欺骗（ARP Spoofing）**：ARP 没有任何认证，攻击者持续发伪造的免费 ARP 声称「网关 IP 的 MAC 是我」，主机无条件更新缓存，出网流量全部先经过攻击者，形成中间人。防御三件套：

- **DHCP Snooping**：在交换机上监听 DHCP 交互，建立 `IP ↔ MAC ↔ 端口` 绑定表。
- **DAI**（Dynamic ARP Inspection，动态 ARP 检测）：用绑定表校验每个 ARP 报文的 `sender_mac/sender_ip` 与端口是否匹配，不匹配直接丢。
- **IP Source Guard**：用同一张绑定表校验数据帧的源 IP，防伪造源地址。

### 3.8 IPv4 首部：20 字节固定部分

IPv4 首部最小 20 字节（IHL=5），带选项最多 60 字节。字段见第五节表格。三个必须理解的机制：

- **TTL**（Time To Live，生存时间）：每经过一台路由器减 1，减到 0 就丢弃并回 ICMP 超时——这是 `traceroute` 的基础（第 08、18 章）。
- **分片**：当数据报大于出接口 MTU 时，按 `片偏移` 以 8 字节为粒度切分，`MF` 标志标记「后面还有片」，`DF` 表示「禁止分片」。所有分片靠 `标识` 字段归组。
- **首部校验和**：只校验首部、不校验载荷，每跳因 TTL 变化都要重算，这也是 IPv6 取消该字段的原因之一。

**4) `arp_sim.py` → ARP 流程与欺骗防御**

```
  [REQUEST] 以太网 目的=ff:ff:ff:ff:ff:ff 源=02:00:00:00:00:0A
          ARP   sender_mac=02:00:00:00:00:0A sender_ip=192.0.2.1
                target_mac=00:00:00:00:00:00 target_ip=192.0.2.2
                → 广播域内所有主机都会收到并交给 ARP 模块处理
  [REPLY] 以太网 目的=02:00:00:00:00:0A 源=02:00:00:00:00:0B
  >>> 结论：ARP Request 广播、ARP Reply 单播。一次广播让所有主机都「被动学习」
```

**结论**：广播请求 + 单播应答 + 300s 老化 + 免费 ARP 四段构成完整的地址解析闭环；末尾 5 行给出 ARP 欺骗抓包特征与 DAI/IPSG 防御思路。

## 五、关键字段 / 报文格式解剖

**IPv4 首部（20 字节固定部分）**

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| 版本 Version | 4 bit | IP 版本号 | 4 |
| 首部长度 IHL | 4 bit | 首部长度，**单位 4 字节** | 5（=20 字节），最大 15（=60 字节） |
| 区分服务 DSCP | 6 bit | 服务质量标记 | 0（默认）、46（EF，语音） |
| 显式拥塞通知 ECN | 2 bit | 拥塞指示 | 00 非 ECN、10 ECT(0)、11 CE |
| 总长度 Total Length | 16 bit | 首部 + 载荷总字节数 | 最大 65535，以太网通常 ≤1500 |
| 标识 Identification | 16 bit | 分片归组 | 每发一个数据报递增 |
| 标志 Flags | 3 bit | 保留 / DF / MF | DF=1 禁止分片，MF=1 后面还有片 |
| 片偏移 Fragment Offset | 13 bit | 分片在原报文中的位置，**单位 8 字节** | 0、185、370…（= 偏移字节/8） |
| 生存时间 TTL | 8 bit | 允许经过的路由跳数 | 初始 64（Linux）/128（Windows）/255（网络设备） |
| 协议 Protocol | 8 bit | 上层协议 | 1 ICMP、2 IGMP、6 TCP、17 UDP、47 GRE、50 ESP、51 AH、89 OSPF、103 PIM |
| 首部校验和 | 16 bit | 仅校验首部，每跳重算 | 首部按 16 位反码求和取反 |
| 源 IP 地址 | 32 bit | 发送方 | — |
| 目的 IP 地址 | 32 bit | 接收方 | — |
| 选项 Options | 0–40 字节 | 记录路由、时间戳、宽松源路由 | 极少使用，有则 IHL > 5 |

**ARP 报文（IPv4 over Ethernet，固定 28 字节）**

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| 硬件类型 | 2 字节 | 链路层类型 | 1 = 以太网 |
| 协议类型 | 2 字节 | 上层协议 | 0x0800 = IPv4 |
| 硬件地址长度 | 1 字节 | MAC 长度 | 6 |
| 协议地址长度 | 1 字节 | IP 长度 | 4 |
| 操作码 Opcode | 2 字节 | 报文类型 | 1 请求 / 2 应答 / 3 RARP 请求 / 4 RARP 应答 |
| 发送方硬件地址 | 6 字节 | 发送方 MAC | 请求方填自己的 MAC |
| 发送方协议地址 | 6→4 字节 | 发送方 IP | 请求方填自己的 IP |
| 目标硬件地址 | 6 字节 | 目标 MAC | 请求时填 `00:00:00:00:00:00` |
| 目标协议地址 | 4 字节 | 目标 IP | 要解析的 IP |

以太网类型字段为 **0x0806** 标识 ARP。`18 字节以太网头与尾 + 28 字节 ARP = 46 字节`，小于最小帧 64 字节，因此会被填充到 64 字节。

## 六、易混概念对比

| 概念 A | 概念 B | 核心区别 | 典型场景 |
|---|---|---|---|
| 子网掩码 | 通配符掩码 | 掩码网络位为 1，通配符网络位为 0（按位取反） | 配 IP 用掩码，写 ACL 用通配符 |
| 网络地址 | 广播地址 | 前者主机位全 0，后者主机位全 1 | .128 与 .191（/26） |
| 私有地址 | 保留/文档地址 | 私有可内部自由用但不路由到公网，保留段连内部使用都受限 | 10/8 vs TEST-NET 192.0.2.0/24 |
| 子网划分 | 超网聚合 | 子网是把大网切小（前缀变长），超网是把小网并大（前缀变短） | /24 → 4×/26 vs 10 条 → 3 条 |
| ARP | 免费 ARP | 前者解析目的 IP 的 MAC，后者宣告自己的 IP↔MAC | 正常通信 vs IP 冲突检测 / VRRP 切换 |
| FLSM | VLSM | 前者所有子网等长，后者按需求变长 | 简单均分 vs 真实部门需求 |

## 七、工程实践与最佳实践

1. **地址规划必须按业务分区并预留连续块**：按「区域→楼层→业务」分层切，让同一汇聚下的网段在数值上连续，未来才能聚合成一条路由。
2. **网段大小按 2 的幂对齐、需求向上取整**：`2^h − 2 ≥ 需求`，不要出现 `/27` 只放 20 台却按 32 台算的错配。
3. **点对点互联用 /30 或 /31**：/30 浪费 2 个，/31（RFC 3021）零浪费，现代设备普遍支持。
4. **每层预留 30%~50% 扩容空间**：地址一旦上线很难回收，规划时留出连续空闲块比后期打补丁省事得多。
5. **VLSM 一律降序分配**：先大后小，避免碎片化导致大块无处安放。
6. **宣告聚合路由时配 `null0` 防环**：有缺口的地址块被聚合宣告后会产生黑洞，用同前缀指向 `null0` 的静态路由兜底（第 08 章）。
7. **ACL 用通配符而不是掩码**：`0.0.0.63` 匹配 /26；写成掩码会导致匹配范围错乱，是最常见的手误之一。
8. **跨网段通信先确认网关，再确认 ARP**：`arp -a` 出现 `incomplete` 说明二层没通，问题在链路而非路由。
9. **缩小广播域**：广播域越大，ARP 广播与泛洪越多；按业务划 VLAN（第 04 章）是控制 ARP 风暴的根本手段。
10. **网关侧开 DAI + DHCP Snooping + IPSG**：三件套共享同一张绑定表，是防 ARP 欺骗成本最低的方案。
11. **文档化 IP 规划表**：记录网段、网关、DHCP 池、用途、负责人；没有规划表的网络在三年后基本无法维护。
12. **避免使用 192.168.0.0/24 作为企业主网段**：它与大量家用路由器默认网段冲突，远程接入（VPN）时会出现回程路由冲突。

## 八、常见陷阱清单

| # | 现象 | 根因 | 排查 / 规避 |
|---|------|------|-------------|
| 1 | 配了 /26 却发现同网段部分 IP 不通 | 算错网络号，把 .130 当成 192.0.2.0/26 里的主机 | 用块大小向下对齐：130→128，属 .128/26 |
| 2 | ACL 只匹配了一个地址 | 把掩码当通配符写（写 255.255.255.192 而非 0.0.0.63） | 通配符 = 255.255.255.255 − 掩码 |
| 3 | VLSM 分配到最后一块放不下 | 需求没降序，或块未按 2 的幂对齐 | 严格降序 + 首次适配 + 剩余按幂切回 |
| 4 | 聚合并告后部分地址不通 | 有缺口的地址块被聚合，形成黑洞 | 配 `null0` 防环路由，或只宣告明细 |
| 5 | IP 冲突告警但找不到设备 | 有人手工配了 DHCP 池内的地址 | 查 ARP 表定位 MAC，用 DHCP Snooping 绑定表溯源 |
| 6 | 169.254.x.x 地址 | DHCP 获取失败，系统自动 APIPA | 查 DHCP 服务/中继/VLAN，这是「没拿到地址」的信号 |
| 7 | ping 网关通、ping 远端不通 | 网关通但缺路由或缺 ARP 到网关 | 先 `arp -a` 看网关是否解析成功，再看路由表 |
| 8 | 子网内可用主机比预期少 2 个 | 忘了减网络号和广播地址 | 可用主机 = 2^h − 2（/31、/32 除外） |
| 9 | 172.16.0.0/12 划成了 /16 的多个块 | 误以为 172.16 就是一个小网 | /12 覆盖 172.16–172.31，共 16 个 /16 |
| 10 | 回环与内网段冲突 | 内网用了 127.x 或 224.x | 127/8 全给回环，224/4 是组播，都不能当主机段 |
| 11 | ARP 表被反复改写 | ARP 欺骗（中间人） | 开 DAI + DHCP Snooping，抓包看 sender_mac 异常 |
| 12 | 更换网关设备后部分主机上网慢 | 老 ARP 缓存未过期 | 发免费 ARP 强制刷新，或等老化 |
| 13 | traceroute 第一跳就是目标 | 目标在直连网段，无三层转发 | 正常现象，说明是同广播域内通信 |
| 14 | 分片后大包丢、小包通 | 中间链路 MTU 小且 DF=1 | 查 MTU，调整 MSS/PMTUD（第 18 章） |
| 15 | 规划表与实际配置不符 | 后期改配置未同步文档 | 配置与规划表双向核对，纳入变更流程 |

9. 说明 ARP 请求为什么用广播、应答为什么用单播。
10. 什么是免费 ARP？它如何用于 IP 冲突检测与网关切换？
11. 描述 ARP 欺骗的原理，并说明 DAI 依赖哪张表工作。
12. 解释 IPv4 首部中 TTL 与首部校验和各自的作用，以及为什么 IPv6 取消了首部校验和。

<summary>参考答案</summary>

1. /11 → 掩码 255.224.0.0，第二字节网络位 3 位，块大小 = 2^5 = 32。`20 ÷ 32 = 0` → 网络地址 **10.0.0.0**；广播 = `10.0.0.0 + 2^21 − 1 = 10.31.255.255`；可用主机 = `2^21 − 2 = 2097150`；范围 **10.0.0.1 ~ 10.31.255.254**。

2. /22 → 第三字节块大小 = 2^(24−22) = 4；`30 ÷ 4 = 7` → `7×4 = 28`；网络 **172.20.28.0**，广播 172.20.31.255；可用主机 = `2^10 − 2 = 1022`。

3. 4 个子网 → 借 2 位 → /26，块大小 64：

| 子网 | 网络地址 | 广播地址 | 可用范围 | 可用数 |
|---|---|---|---|---|
| 192.0.2.0/26 | 192.0.2.0 | 192.0.2.63 | .1 ~ .62 | 62 |
| 192.0.2.64/26 | 192.0.2.64 | 192.0.2.127 | .65 ~ .126 | 62 |
| 192.0.2.128/26 | 192.0.2.128 | 192.0.2.191 | .129 ~ .190 | 62 |
| 192.0.2.192/26 | 192.0.2.192 | 192.0.2.255 | .193 ~ .254 | 62 |

4. 降序 80、25、12：80 → `2^7−2=126 ≥ 80` → /25，192.0.2.0，容量 126；25 → `2^5−2=30 ≥ 25` → /27，192.0.2.128，容量 30；12 → `2^4−2=14 ≥ 12` → /28，192.0.2.160，容量 14。剩余空闲：`192.0.2.176/28`、`.192/27`、`.224/27`（共 16+32+32 = 80 个地址）。已用 176/256 = 68.75%。

5. 聚合：`198.51.100.0/25 + 198.51.100.128/25 → 198.51.100.0/24`；`203.0.113.0/26 + 203.0.113.64/26 → 203.0.113.0/25`，`.128/26 + .192/26 → 203.0.113.128/25`，`.0/25 + .128/25 → 203.0.113.0/24`。最终 **2 条**：`198.51.100.0/24`、`203.0.113.0/24`。节省率 = `(6−2)/6 = 66.7%`。

6. `255.255.254.0` = 前 23 位为 1 → 前缀 **/23**；通配符 = `255.255.255.255 − 255.255.254.0 = 0.0.1.255`；可用主机 = `2^9 − 2 = 510`。

7. `/26` 的块大小为 64。PC-A `192.0.2.100` 落入 `192.0.2.64/26`（范围 .65~.126），而网关 `192.0.2.1` 属于 `192.0.2.0/26`（范围 .1~.62）——**网关在本子网之外，PC-A 根本 ARP 不到网关**，所以连 ping 都不通。PC-B `192.0.2.10` 与网关同在 `192.0.2.0/26`，正常。修复：把 PC-A 掩码改为 `/25`（这样 .1 与 .100 同在 `192.0.2.0/25`），或把网关地址改到 `192.0.2.65` 一类同子网地址。

8. ① 确认接入口 VLAN 与 DHCP 池所在 VLAN 是否一致；② 查 DHCP 服务器/中继是否可达（`ip helper-address` 是否配）；③ 查地址池是否耗尽（`show ip dhcp pool`）；④ 抓包看是否发出 DISCOVER、是否有 OFFER 回来；⑤ 查接入交换机是否开了 DHCP Snooping 但未配信任口。

9. 请求方**不知道**目标 MAC，只能向整个广播域广播「谁是 X」，广播能被所有主机收到。应答方**已经知道**请求方的 MAC 与 IP（都在请求报文里），所以单播回复，减少广播域内的无用流量。

10. 免费 ARP 是主机主动广播「我的 IP ↔ 我的 MAC」的 ARP 报文（`sender_ip = target_ip`）。用途①：若收到别的应答，说明 IP 冲突；用途②：网卡更换或 VRRP/HSRP 切换后，广播一次即可让全网立即更新缓存，无需等待老化。

11. 攻击者持续发送伪造 ARP，把网关 IP 映射到自己的 MAC，主机无条件更新缓存，导致出网流量先经过攻击者（中间人）。DAI 依赖 **DHCP Snooping 生成的 IP↔MAC↔端口 绑定表**，逐报文校验 ARP 的 sender 信息与入端口，不匹配即丢弃。

12. TTL 每跳减 1，防止报文在环路中无限转发，也用于 traceroute 逐跳探测。首部校验和只校验首部、不校验载荷，保证首部在传输中不出错。IPv6 取消首部校验和，是因为链路层（以太网）与传输层（TCP/UDP）已有校验，重复校验收益低，取消后路由器无需每跳重算，转发效率更高。
