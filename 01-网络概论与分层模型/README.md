# 第 01 章 · 网络概论与分层模型

> **一句话定位**：把「一个数据包从应用层代码变成网线上的电平」这条主线走通，建立全书统一的坐标系——分层模型、封装解封装、时延与性能指标。
> **前置知识**：无（本章是全书起点） ｜ **难度**：★☆☆ ｜ **建议投入**：90 分钟

## 一、学习目标

1. 能说出 ARPANET（1969）到互联网、再到云网一体的关键时间节点与技术驱动力。
2. 能对比电路交换、报文交换、分组交换三种方式的时延构成与适用场景，并算出给定参数下的端到端时延。
3. 会写出协议三要素（语法 / 语义 / 同步），并用一个具体协议（如 TCP 首部）指出三要素分别落在哪里。
4. 能画出 OSI 七层、TCP/IP 四层、五层教学模型的对照表，并说明每一层的 PDU 名称。
5. 能完整复述封装与解封装过程，说出每层头部字节数、累计帧长与 SDU/PCI/PDU 的关系。
6. 能计算发送时延、传播时延、处理时延、排队时延、时延带宽积、RTT 与利用率。

## 二、核心概念总览

先看本章骨架：数据自顶向下经过协议栈，每层加一个头部；横向看是同层对话，纵向看是下层为上层服务。

```
   应用层   [ HTTP 载荷 100B ]                        <-- 用户数据
      |  加密 / 编码（表示层、会话层在 TCP/IP 中并入应用层）
      v
   传输层   [ TCP 头 20B | 载荷 100B ]      = 段 Segment (120B)
      v
   网络层   [ IP 头 20B | 段 120B ]         = 包 Packet  (140B)
      v
   链路层   [ 帧头 14B | 包 140B | FCS 4B ] = 帧 Frame   (158B)
      v
   物理层   前导码 8B + 比特流 1264 bit      = 比特 Bit
      v
   ================== 物理介质 ==================>
      v
   对端自底向上逐层剥头，任一层校验失败即丢弃
```

| 层次 | PDU 名称 | 本章涉及的头部长度 | 寻址标识 | 典型设备 |
|------|---------|------------------|---------|---------|
| 应用层 | 数据 / 报文 Message | 视协议而定（HTTP 起始行等） | 域名 / URL | 服务器、客户端 |
| 传输层 | 段 Segment（TCP）/ 数据报 Datagram（UDP） | TCP 固定 20B | 端口号（16 位） | 主机协议栈 |
| 网络层 | 包 Packet | IPv4 固定 20B | IP 地址（32 位） | 路由器 R1/R2 |
| 数据链路层 | 帧 Frame | 以太网头 14B + FCS 4B | MAC 地址（48 位） | 交换机 SW1/SW2 |
| 物理层 | 比特 Bit | 前导码 7B + SFD 1B | 无（只关心电平和时钟） | 中继器、集线器 |

横向对比一下「什么时候用哪套模型」：说「二层交换机」用的是 OSI 口径，说「网络接口层」用的是 TCP/IP 口径，说「物理层问题」在五层口径里单独成层。三套模型描述的是同一批协议，只是切分粒度不同。本章后续所有分析，默认使用五层模型，因为它在讲封装时最方便。

## 三、机制详解

### 3.1 网络发展脉络：从 4 个节点到云网一体

设计动机始终只有一个：**让异构的计算机能互相通信，且网络本身要能扛住节点失效**。分阶段看：

1. **ARPANET（1969 年 10 月）**：首批 4 个节点——UCLA、SRI、UC Santa Barbara、University of Utah，第一条链路速率 50 kbit/s。核心思想是分组交换（Packet Switching）与分布式路由。
2. **TCP/IP 体系确立**：1981 年发布 RFC 791（IPv4）与 RFC 793（TCP）。1983 年 1 月 1 日 ARPANET 完成「Flag Day」切换，全网由 NCP 换为 TCP/IP，这是现代互联网的起点。
3. **OSI 参考模型（1984）**：ISO 发布 ISO/IEC 7498-1，给出七层模型。它权威但实现复杂，最终被更务实的 TCP/IP 体系在工程上胜出。
4. **万维网与商业化（1990s）**：1991 年 WWW 公开，1995 年 NSFNET 骨干退役，互联网走向商用。
5. **云网一体（2010s 至今）**：数据中心内部东西向流量成为主体，VXLAN（8 字节头 + 24 位 VNI）等 Overlay 技术把二层扩展搬到三层网络之上，网络从「连通工具」变成「可编排资源」。

### 3.2 交换方式：电路 / 报文 / 分组

**为什么要有三种方式**：早期电话网要求稳定连续的带宽，所以用电路交换；数据通信突发性强，独占电路太浪费，于是演化出分组交换。

| 方式 | 建立阶段 | 转发单位 | 时延构成 | 典型场景 |
|------|---------|---------|---------|---------|
| 电路交换 | 需要（拨号） | 比特流（独占时隙/频率） | 传播时延为主，无排队 | PSTN 电话网 |
| 报文交换 | 不需要 | 整个报文 | 每跳都要收完整报文再转发 | 早期电报 |
| 分组交换 | 不需要 | 分组（packet） | 发送 + 传播 + 处理 + 排队 | 互联网、以太网 |

三种方式的端到端时延，可直接用公式对比（设报文长 x bit，分组长 p bit，链路数 k 条，每条速率 R bit/s）：

- 报文交换：`T_msg = k × (x / R)`
- 分组交换：`T_pkt = (k − 1) × (p / R) + (x / R)`

代入 x = 8×10⁶ bit（1 MB）、p = 1000 bit、R = 1 Mbit/s、k = 3 条链路：

- 报文交换：`T_msg = 3 × (8×10⁶ / 1×10⁶) = 3 × 8 = 24 s`
- 分组交换：`T_pkt = 2 × (1000 / 1×10⁶) + 8×10⁶ / 1×10⁶ = 0.002 + 8 = 8.002 s`

结论：分组交换靠**流水线**把时延从 24 s 降到 8.002 s，这是互联网选择分组交换的根本原因。代价是每个分组要额外携带头部（本算例中每 1000 bit 里就有头部开销），且分组到达可能乱序。

### 3.3 协议三要素：语法 / 语义 / 同步

协议（Protocol）是通信双方必须共同遵守的规则集合，由三个要素构成：

1. **语法（Syntax）**：数据与控制信息的**格式**。例如 TCP 首部固定 20 字节，第 1~2 字节是源端口，第 3~4 字节是目的端口，第 13 字节低 6 位是标志位。
2. **语义（Semantics）**：每个字段的**含义与要完成的动作**。例如 TCP 首部中 SYN=1 表示请求建立连接，ACK=1 表示确认号有效，收到 SYN 后要回 SYN+ACK。
3. **同步（Synchronization）**：事件的**先后顺序与时序约束**。例如 TCP 三次握手必须严格按 SYN → SYN+ACK → ACK 的顺序；OSPF Hello 报文默认每 10 秒发一次。

可以这样记忆：语法管「长什么样」，语义管「是什么意思、要做什么」，同步管「什么时候做、先后顺序」。

### 3.4 OSI 七层与 TCP/IP 四层 / 五层的对应

**为什么会有多套模型**：OSI 是「先设计标准再实现」，分层严谨但落地慢；TCP/IP 是「先实现再总结标准」，务实但上三层界限模糊。

1. OSI 七层（自下而上）：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。
2. TCP/IP 四层：网络接口层、网际层、传输层、应用层。
3. 五层教学模型：物理层、数据链路层、网络层、传输层、应用层。

对应关系为：OSI 的「应用层 + 表示层 + 会话层」合并为 TCP/IP 的应用层；OSI 的「物理层 + 数据链路层」合并为 TCP/IP 的网络接口层。详细的逐层对照与协议映射见本章脚本 `layer_mapping.py`。

### 3.5 封装与解封装：每层加了什么

发送方自顶向下**封装（Encapsulation）**，接收方自底向上**解封装（Decapsulation）**。以 100 字节应用数据、TCP/IPv4/以太网为例：

1. 应用层产出 100 B 数据。
2. 传输层加 TCP 首部 20 B（无选项），得 120 B 的**段**。
3. 网络层加 IPv4 首部 20 B，得 140 B 的**包**。
4. 数据链路层加以太网头 14 B（目的 MAC 6 + 源 MAC 6 + 类型 2），并在尾部加 FCS 4 B，得 158 B 的**帧**。
5. 物理层加前导码 7 B + SFD 1 B，得 `(158 + 8) × 8 = 1328 bit` 上线。

接收方反向执行 5→1：先做位同步、比对 FCS；FCS 通过才上交网络层，网络层校验首部校验和并判断目的 IP；再交给传输层按端口找套接字。任一环节校验失败直接丢帧，不会通知应用。

以太网规定**最小帧 64 字节**（不含前导码）。若上层数据太少导致帧长不足 64 B，网卡会填充（Pad）到 64 B，目的是保证冲突检测（CSMA/CD）能在最坏情况下听到冲突。本算例帧长 158 B，无需填充。

### 3.6 SDU、PCI 与 PDU 的关系

在第 N 层内部，数据被拆成三部分理解：

- **SDU（Service Data Unit，服务数据单元）**：第 N 层从第 N+1 层收到的「净载荷」。
- **PCI（Protocol Control Information，协议控制信息）**：第 N 层自己加的头部（有时还有尾部）。
- **PDU（Protocol Data Unit，协议数据单元）**：`PDU = PCI + SDU`。

关键关系是：**第 N 层的 SDU 等于第 N+1 层的 PDU**。以编号从小到大（物理层=1、应用层=5）为例：

```
N+1 层 PDU  ==  N 层 SDU          （上层交下来的载荷）
N   层 PDU  ==  N 层 PCI + N 层 SDU
```

举例：网络层收到的 SDU 就是传输层的段（120 B），网络层加上 20 B PCI 后产出网络层 PDU——包（140 B）。理解这条链，就能理解「为什么改一个 MTU 会牵动从 IP 到 TCP 的连锁反应」。

### 3.7 性能指标：时延四兄弟与带宽时延积

网络性能不是一个数，而是一组数。最常混淆的是**带宽**与**吞吐量**：

- **带宽（Bandwidth）**：链路能承载的最高数据率，单位 bit/s。注意它和信号带宽（Hz，频率范围）不是一回事。
- **吞吐量（Throughput）**：单位时间内**实际**通过的数据量，永远 ≤ 带宽。瓶颈链路的带宽决定端到端吞吐量上限。

时延由四部分构成（这是全章最需要背熟的一组公式）：

| 时延类型 | 公式 | 影响因素 | 量级示例 |
|---------|------|---------|---------|
| 发送时延（传输时延） | `d_tx = L / R` | 帧长 L、带宽 R | 1500 B / 100 Mbit/s = 0.12 ms |
| 传播时延 | `d_prop = d / v` | 距离 d、介质中光速 v | 1000 km / 2×10⁸ m/s = 5 ms |
| 处理时延 | 由设备决定 | CPU、查表复杂度 | 交换机约 20 µs |
| 排队时延 | `d_queue = 队列积压比特 / R` | 拥塞程度 | 随利用率上升急剧增大 |

**时延带宽积（BDP）= R × d_prop**，物理含义是「链路上在途的比特数」。例：R = 100 Mbit/s、d_prop = 5 ms，则 `BDP = 1×10⁸ × 5×10⁻³ = 5×10⁵ bit = 62500 B ≈ 41.7 个 1500 B 帧`。这就是高带宽长链路必须扩大 TCP 窗口的原因：管道里能装这么多数据，发送方却只有很小的窗口，链路就跑不满。

**往返时间（RTT）** 是「一个比特从发送方到接收方再回来」的时间。严格说 RTT 只含往返传播时延，但工程上测到的 RTT 还包含发送、处理与排队。利用率与排队时延的关系是：`d_queue ≈ d_tx × U / (1 − U)`（M/M/1 近似），当利用率 U 趋近 1 时，排队时延趋于无穷——这就是链路「一忙就卡」的数学解释。

### 3.8 标准化组织与 RFC 体系

| 组织 | 全称 | 负责范围 | 代表标准 |
|------|------|---------|---------|
| IETF | Internet Engineering Task Force | 互联网协议（非官方但事实权威） | RFC 791、RFC 793、RFC 8200 |
| IEEE | Institute of Electrical and Electronics Engineers | 底层与链路层（802 系列） | 802.3 以太网、802.11 WLAN |
| ITU-T | International Telecommunication Union - Telecom | 电信标准 | X.509 证书、G.711 话音编码 |
| ISO | International Organization for Standardization | 通用标准与 OSI 模型 | ISO/IEC 7498-1（OSI） |

RFC（Request for Comments）体系有几点必须记住：它由 IETF 发布，编号一旦分配**永不回收**；成熟度分 Proposed Standard → Internet Standard（STD 号），此外还有 Informational、Experimental、Historic 与 BCP。RFC 2119 定义了大写关键字 MUST / SHOULD / MAY 的强制程度——读协议时看到 MUST 表示强制实现，SHOULD 表示强烈建议，MAY 表示可选。

## 四、动手验证

本章三个脚本都在文件所在目录直接运行，零依赖、不联网、秒级完成。

### 4.1 `osi_layers_demo.py` —— 逐层封装与解封装

**演示什么**：把 100 字节应用数据逐层封装，打印每层 PDU 名、新增字节、累计长度；再自底向上解封装。

**运行命令**：`python3 osi_layers_demo.py`（可传参改载荷，如 `python3 osi_layers_demo.py 8`）。

**关键输出片段**：

```
层次            PDU 名称                     新增        累计
----------------------------------------------------------------
7 应用层        数据/报文 (Message)           —        100B
4 传输层        段 (Segment)                +20B        120B
3 网络层        包 (Packet)                 +20B        140B
2 数据链路层     帧 (Frame)                  +18B        158B
1 物理层        比特 (Bit)                   +8B        166B
```

**从输出看出的结论**：每层只加自己的头部，PDU 名随层而变；把载荷改成 8 字节时，帧长只有 66 B，会触发「小于 64 B 需填充」的边界提示——这正是最小帧规则的由来。

### 4.2 `delay_budget.py` —— 时延预算与 BDP

**演示什么**：给 3 条链路（1 Gbps/100 m、100 Mbps/1000 km、10 Mbps/10 km）逐项算四种时延、BDP、RTT，并对比纯传播 RTT 与完整往返时间。

**运行命令**：`python3 delay_budget.py`（可传帧长，如 `python3 delay_budget.py 64`）。

**关键输出片段**：

```
链路          发送时延 L/R        传播时延 d/v       时延带宽积 R*d/v
----------------------------------------------------------------
PC1-SW1           0.012 ms           0.435 us            100 bit
SW1-R1            0.120 ms           5.000 ms         500000 bit
R1-PC2            1.200 ms           0.050 ms           5000 bit
----------------------------------------------------------------
>>> 单程总时延 = 6.492 ms
>>> 纯传播 RTT = 10.101 ms
>>> 完整往返总时间 = 12.985 ms
```

**从输出看出的结论**：长距离链路上传播时延占绝对主导（本算例约 78%）；把中继链路带宽从 100 Mbps 提到 1 Gbps，单程时延从 6.492 ms 仅降到 6.384 ms——**带宽买不来低时延**，这是排查「带宽够但延迟高」类故障的第一原则。

### 4.3 `layer_mapping.py` —— 三套模型对照

**演示什么**：打印 OSI 七层 / TCP-IP 四层 / 五层模型的逐层对照表、8 个协议的落点映射、以及同层逻辑通信示意图。

**运行命令**：`python3 layer_mapping.py`。

**关键输出片段**：

```
协议           OSI 七层落点     五层落点        四层落点
----------------------------------------------------------------
TLS           表示层          应用层          应用层
ARP           网络层          网络层          网际层
Ethernet      数据链路层       数据链路层       网络接口层
```

**从输出看出的结论**：TLS 在 OSI 里属表示层，在 TCP/IP 里并入应用层；ARP 的层级归属在两套模型里不一致。看到「第几层协议」的说法，一定要先确认对方用的是哪套模型。

## 五、关键字段 / 报文格式解剖

本章核心是「头部字节账」，下表把一次典型封装涉及的字段全部列出（以 IPv4 + TCP + 以太网为例）：

| 字段 | 长度 | 作用 | 常见取值 |
|------|------|------|---------|
| 目的 MAC | 6 B | 链路层接收方标识 | `02:00:00:00:00:0B` |
| 源 MAC | 6 B | 链路层发送方标识 | `02:00:00:00:00:0A` |
| 类型 / 长度 | 2 B | 上层协议（>1500 表示类型） | `0x0800` 表示 IPv4 |
| 帧载荷 | 46~1500 B | 携带的网络层包 | 含 IPv4 包 140 B |
| FCS | 4 B | CRC-32 差错检测 | 由发送方计算，收方校验 |
| IPv4 版本 | 4 bit | IP 版本号 | `4` |
| 首部长度 | 4 bit | 以 4 字节为单位 | `5`（即 20 B） |
| 总长度 | 16 bit | 首部 + 数据总字节数 | 最大 65535 B |
| 标识 | 16 bit | 分片重组标识 | 全局递增 |
| 标志 | 3 bit | DF / MF | DF=1 表示禁止分片 |
| 片偏移 | 13 bit | 分片在原包中的位置 | 以 8 字节为单位 |
| TTL | 8 bit | 生存时间 | 初始 64 / 128 / 255 |
| 协议 | 8 bit | 上层协议号 | 6=TCP，17=UDP，1=ICMP |
| 首部校验和 | 16 bit | 仅校验 IP 首部 | 每跳重算 |
| 源 / 目的 IP | 各 4 B | 网络层寻址 | `192.0.2.1` / `198.51.100.1` |
| TCP 源 / 目的端口 | 各 2 B | 传输层寻址 | 1024~65535 为动态端口 |
| 序号 | 4 B | 字节流编号 | 随机初始值 |
| 确认号 | 4 B | 期望收到的下一字节 | 累积确认 |
| 数据偏移 | 4 bit | TCP 首部长度（4 字节单位） | `5` 表示 20 B |
| 标志位 | 6 bit | URG/ACK/PSH/RST/SYN/FIN | SYN=1 建连 |
| 窗口 | 2 B | 接收窗口大小 | 最大 65535（可加窗口扩大因子） |
| 校验和 | 2 B | 含伪首部 | 覆盖首部 + 数据 |
| 紧急指针 | 2 B | 配合 URG 使用 | 平时为 0 |

## 六、易混概念对比

| 概念 A | 概念 B | 核心区别 | 典型场景 |
|--------|--------|---------|---------|
| 带宽 Bandwidth | 吞吐量 Throughput | 前者是链路上限，后者是实际通过量 | 100 Mbps 链路实测 92 Mbps |
| 发送时延 | 传播时延 | 前者 = L/R，看带宽；后者 = d/v，看距离与光速 | 提高带宽只降发送时延 |
| 报文交换 | 分组交换 | 前者整报文存储转发，后者可流水线 | 互联网用分组交换 |
| OSI 七层 | TCP/IP 四层 | 上三层是否合并、下两层是否合并 | 考试用七层，写代码用四层 |
| PDU | SDU | PDU = PCI + SDU，SDU 是净载荷 | 段是传输层 PDU、网络层 SDU |
| 电路交换 | 分组交换 | 是否独占资源 | 电话网 vs 互联网 |

## 七、工程实践与最佳实践

1. **排障按五层自底向上走**——因为物理层问题占现场故障的比例最高（网线、光模块、双工不匹配），先看物理能最快排除掉一大批「假故障」。
2. **记住 1500/20/20/14/4 这组数字**——MTU=1500、IPv4 头 20、TCP 头 20、以太网头 14、FCS 4。算分片、算 MSS、算 VXLAN 开销全靠它们。
3. **区分「带宽不够」和「时延高」**——带宽不够表现为吞吐量上不去、丢包；时延高表现为交互卡顿。前者扩容有效，后者加带宽无效，必须查路由跳数、排队与链路利用率。
4. **任何跨广域的应用都要先算 BDP**——BDP 决定需要多大的 TCP 窗口才能跑满链路。1 Gbps × 50 ms 的 BDP 是 625 万字节，默认窗口根本不够。
5. **把 RTT 当作基线而非绝对值**——同城 RTT 应 < 2 ms，跨省 10~30 ms，跨国 100~200 ms。实测明显偏高时，先看是否绕路。
6. **协议实现优先看 RFC 里的 MUST**——RFC 2119 的关键字代表强制程度，厂商实现差异往往就出在 SHOULD/MAY 的取舍上。
7. **文档网段只用于教学**——`192.0.2.0/24`、`198.51.100.0/24`、`203.0.113.0/24`（RFC 5737）与 `2001:db8::/32`（RFC 3849）专供示例，写实验方案时直接用它们，避免误伤真实地址。
8. **利用率长期 > 70% 就该扩容**——由 `d_queue ≈ d_tx × U/(1−U)`，U=0.7 时排队时延已是发送时延的 2.3 倍，U=0.9 时达 9 倍。
9. **抓包先看三层/四层再深入**——先用 Wireshark 看 Ethernet → IP → TCP 的头，确认 MAC、TTL、标志位是否符合预期，再去看应用层。
10. **设备命名与地址规划保持可聚合**——按业务分区、按区域分配连续网段，后期做路由聚合时能显著减少路由表条目。

## 八、常见陷阱清单

| # | 现象 | 根因 | 排查 / 规避 |
|---|------|------|-------------|
| 1 | 说「二层设备」对方理解不一致 | OSI 与 TCP/IP 层号口径不同 | 明确用哪套模型，或直接说功能（如「交换机」） |
| 2 | 小文件传输正常，大文件卡死 | MTU 黑洞，ICMP 被中间设备丢弃 | 检查 `ip link` MTU，测试 PMTUD，必要时调小 MSS |
| 3 | 链路带宽充足但吞吐量上不去 | BDP 大而 TCP 窗口小 | 计算 BDP，启用窗口扩大因子或调大窗口 |
| 4 | 时延随业务量增长而急剧上升 | 排队时延按 U/(1−U) 非线性增长 | 监控链路利用率，控制在 70% 以下 |
| 5 | 认为「升级带宽能降低时延」 | 混淆发送时延与传播时延 | 记住传播时延由 d/v 决定，与 R 无关 |
| 6 | 帧长算出来小于 64 B 却以为能发 | 忽略以太网最小帧与填充 | 小于 64 B 会被填充，抓包看到的是填充后的长度 |
| 7 | 把前导码算进有效帧长 | 前导码只做位同步，不上送上层 | 帧长统计不含 7 B 前导码 + 1 B SFD |
| 8 | 把 IP 首部长度当成固定 20 B | IPv4 首部可带选项，最长 60 B | 用「首部长度」字段 × 4 计算真实长度 |
| 9 | 直接用 IP 地址做端到端通信 | 同一网段通信实际按 MAC 转发 | 记住「同网段看 MAC，跨网段看 IP」 |
| 10 | 用「数据包」泛指一切 PDU | 各层 PDU 名不同，沟通时易偏差 | 传输层叫段、网络层叫包、链路层叫帧 |
| 11 | 以为 RTT 只由传播时延决定 | 实测 RTT 含发送、处理、排队 | 高负载下 RTT 会明显高于纯传播 RTT |
| 12 | 迷信 RFC 编号越大越新越权威 | RFC 仅 Informational 也占编号 | 看成熟度字段与 STD/BCP 归类 |

## 九、自测练习

1. 说明电路交换、报文交换、分组交换三者的时延构成差异，并指出互联网为何选分组交换。
2. 写出协议三要素，并分别用 TCP 的「源端口字段」「SYN 标志」「三次握手顺序」对应到三要素。
3. 计算题：报文长 1 MB（8×10⁶ bit），分组长 1000 bit，链路 4 条，每条速率 2 Mbit/s。分别求报文交换与分组交换的时延。
4. 计算题：帧长 1500 B，链路速率 1 Gbit/s，求发送时延。
5. 计算题：距离 2000 km，光纤中光速 2×10⁸ m/s，求单程传播时延与纯传播 RTT。
6. 计算题：R = 1 Gbit/s、d_prop = 50 ms，求 BDP（分别用 bit、字节、1500 B 帧个数表示）。
7. 计算题：发送时延 0.12 ms，链路利用率 0.8，按 `d_queue ≈ d_tx × U/(1−U)` 估算排队时延。
8. 排障题：某跨城专线延迟实测 40 ms，扩容带宽后仍为 40 ms，解释原因。
9. 排障题：总部到分支 ping 通、丢包率 0.1%，但大文件传输速率只有带宽的 30%，列出至少三条排查方向。
10. 用 100 字节应用数据，手工算出 TCP/IPv4/以太网各层 PDU 长度与最终比特数。
11. 说明 SDU 与 PDU 的关系，并指出「网络层的 SDU」等于「哪一层的 PDU」。
12. 列举 IETF、IEEE、ITU-T、ISO 各负责的一类标准，并各举一个具体标准。

<details>
<summary>参考答案</summary>

1. 电路交换建立连接后独占资源，时延以传播时延为主，无排队；报文交换以整个报文为单位存储转发，每跳需收完才能转发，时延大；分组交换把报文切成小分组，可流水线转发并复用链路。互联网选分组交换是因为其突发流量适配性好、链路利用率高、抗节点失效能力强。

2. 语法 = 源端口字段的位置与长度（固定 20 B 首部中第 1~2 字节，16 位）；语义 = SYN=1 表示请求建立连接；同步 = 三次握手必须按 SYN → SYN+ACK → ACK 的先后顺序进行。

3. 报文交换：`T_msg = k × x/R = 4 × (8×10⁶ / 2×10⁶) = 4 × 4 = 16 s`。分组交换：`T_pkt = (k−1) × p/R + x/R = 3 × (1000 / 2×10⁶) + 8×10⁶ / 2×10⁶ = 0.0015 + 4 = 4.0015 s`。分组交换约为报文交换的 1/4。

4. `d_tx = L/R = (1500 × 8) / (1×10⁹) = 12000 / 1×10⁹ = 1.2×10⁻⁵ s = 12 µs`。

5. `d_prop = d/v = (2000 × 1000) / (2×10⁸) = 2×10⁶ / 2×10⁸ = 1×10⁻² s = 10 ms`；纯传播 `RTT = 2 × 10 ms = 20 ms`。

6. `BDP = R × d_prop = 1×10⁹ × 50×10⁻³ = 5×10⁷ bit`；换算字节 `5×10⁷ / 8 = 6.25×10⁶ B = 6250000 B`；折算 1500 B 帧 `6250000 / 1500 ≈ 4167 个`。

7. `d_queue ≈ 0.12 ms × 0.8 / 0.2 = 0.12 × 4 = 0.48 ms`。

8. 扩容只降低发送时延与排队时延，而跨城专线的时延主项是传播时延（`d = d_prop = 距离/光速`）。40 ms 对应约 4000 km 单程传播距离，带宽提升不改变光速，故时延不变。

9. 可能方向：① 存在 MTU 黑洞导致大包被丢弃并触发重传；② 链路存在丢包（0.1%）使 TCP 拥塞窗口长期偏小、无法填满 BDP；③ BDP 大而窗口小，接收窗口/拥塞窗口成为瓶颈；④ 中间链路存在限速策略或 QoS。

10. 应用数据 100 B → 加 TCP 头 20 B 得段 120 B → 加 IPv4 头 20 B 得包 140 B → 加以太网头 14 B + FCS 4 B 得帧 158 B → 加前导码 8 B 后 `(158+8) × 8 = 1328 bit`。

11. `PDU = PCI + SDU`，第 N 层的 SDU 等于第 N+1 层的 PDU。网络层的 SDU 等于传输层的 PDU，即「段」。

12. IETF 负责互联网协议（RFC 791 IPv4）；IEEE 负责链路与底层（IEEE 802.3 以太网）；ITU-T 负责电信标准（X.509）；ISO 负责通用标准（ISO/IEC 7498-1 OSI 参考模型）。

</details>
