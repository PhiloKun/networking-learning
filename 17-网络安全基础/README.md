## 二、核心概念总览

安全不是单点设备，而是「按攻击面分层设防」的体系。下图把本章骨架一次铺开：

```
   攻击者的目标                                          防守者的对应手段
  ┌────────────────────────────────────┐    ┌──────────────────────────────────┐
  │ L7 应用层：注入/越权/0day            │    │ WAF、代码审计、最小权限、HTTPS     │
  ├────────────────────────────────────┤    ├──────────────────────────────────┤
  │ L4 传输层：SYN Flood / 端口扫描       │    │ 状态防火墙(会话表)、SYN Cookie     │
  ├────────────────────────────────────┤    ├──────────────────────────────────┤
  │ L3 网络层：IP 欺骗 / 反射放大 DDoS    │    │ ACL + uRPF 反向路径检查、限速清洗  │
  ├────────────────────────────────────┤    ├──────────────────────────────────┤
  │ L2 链路层：ARP 欺骗 / MAC 洪泛        │    │ DAI + IP Source Guard + 端口安全   │
  ├────────────────────────────────────┤    ├──────────────────────────────────┤
  │ L1 物理层：搭线窃听 / 私接             │    │ 机房门禁、端口隔离、802.1X 准入    │
  └────────────────────────────────────┘    └──────────────────────────────────┘
     越往下越接近物理，越难用软件弥补；越往上攻击面越广，越要靠策略与流程
```

配套的一张「控制类型」表：

| 控制类型 | 作用时机 | 典型技术 | 典型设备 |
|---|---|---|---|
| 预防性 | 攻击发生前 | ACL、802.1X、防火墙策略、IPsec | 交换机、防火墙、路由器 |
| 检测性 | 攻击进行中 | IDS、NetFlow 基线告警、DAI 日志 | IDS、探针、交换机 |
| 纠正性 | 攻击发生后 | 隔离 VLAN、黑洞路由、封禁 IP | 防火墙、路由器 |
| 恢复性 | 处置之后 | 配置回滚、备份恢复、取证复盘 | 网管平台、日志系统 |

`192.0.2.0/24`（办公网）、`198.51.100.0/24`（对外服务网）、`203.0.113.0/24`（骨干链路）是本章后续所有案例统一使用的教学网段。

## 三、机制详解

### 3.1 安全三要素 CIA 与威胁模型

**为什么这样设计**：安全讨论必须先定义「保护什么、防谁、防到什么程度」，否则就会陷入「加一堆设备但不知道挡住了什么」的困境。CIA 是最小完备集。

1. **机密性（Confidentiality）**：信息只被授权者读取。被破坏的典型是明文嗅探、数据泄露。对应技术：加密（IPsec、TLS）、访问控制。
2. **完整性（Integrity）**：信息未被未授权篡改。被破坏的典型是中间人篡改、报文校验缺失。对应技术：哈希校验（ESP 的 ICV、FCS）、数字签名。
3. **可用性（Availability）**：授权者能按需访问。被破坏的典型是 DDoS、勒索。对应技术：冗余、限速、清洗、SYN Cookie。

威胁模型的常见框架是 **STRIDE**，把威胁分成六类：伪造身份（Spoofing）、篡改（Tampering）、否认（Repudiation）、信息泄露（Information Disclosure）、拒绝服务（Denial of Service）、权限提升（Elevation of Privilege）。本章的 ARP 欺骗属于 Spoofing，中间人同时命中 Spoofing + Tampering，SYN Flood 与端口扫描属于 Denial of Service 的前置。

> 现实里：设备侧看「zone-based firewall」(Cisco IOS-ZBF) 里的 `class-map` + `policy-map`，就是把 CIA 变成「哪些流量允许、哪些做检查、哪些直接丢」的策略。

### 3.2 访问控制列表 ACL：顺序匹配与通配符

**解决什么问题**：在设备接口上做「谁可以访问谁」的最基本的包过滤。ACL 的正确性几乎全压在「顺序」和「通配符」两件事上。

**ACL 的三条铁律**：

1. **自上而下顺序匹配**，命中第一条规则立刻执行动作（permit / deny）并停止，绝不会继续往下比较。
2. **每条 ACL 末尾隐含 `deny any`**（思科叫 implicit deny any，华为叫「未匹配即丢弃」），所以「只写 permit」等于「其余全部拒绝」。
3. **标准 ACL 只能匹配源地址**；**扩展 ACL 能匹配协议、源目地址、源目端口、标志位**。

**通配符掩码（Wildcard Mask）比对算法**：

1. 取规则地址 `rule`、报文地址 `packet`、通配符 `wc`，三者都按 32 位无符号整数处理。
2. 计算 `mask = NOT wc`，把「忽略位」清零，只留下必须一致的比特位。
3. 计算 `diff = (packet XOR rule) AND mask`。
4. 若 `diff == 0` 则命中，否则不命中。

通配符里**位为 0 表示必须匹配、位为 1 表示忽略**。`host 1.2.3.4` 等价于通配符 `0.0.0.0`（32 位全比较），`any` 等价于 `255.255.255.255`（32 位全忽略）。

配置示例（思科风格，接口入方向）：

```
interface GigabitEthernet0/1
 ip access-group 100 in
!
access-list 100 permit tcp 192.0.2.0 0.0.0.255 host 198.51.100.10 eq 443
access-list 100 deny   tcp any any eq 23
access-list 100 permit icmp 192.0.2.0 0.0.0.255 any
access-list 100 permit udp any 198.51.100.0 0.0.0.255 eq 53
```

华为风格（编号 3000~3999 为高级 ACL，rule 5 步长便于插入）：

```
acl number 3000
 rule 5  permit tcp source 192.0.2.0 0.0.0.255 destination 198.51.100.10 0 eq 443
 rule 10 deny   tcp destination-port eq telnet
 rule 15 permit icmp source 192.0.2.0 0.0.0.255
 rule 20 permit udp destination 198.51.100.0 0.0.0.255 destination-port eq domain
```

**时间 ACL** 用 `time-range` 把规则绑定到时间段，例如只允许工作时间访问：`access-list 101 permit tcp 192.0.2.0 0.0.0.255 any eq 22 time-range WORK`，配合 `time-range WORK periodic weekdays 9:00 to 18:00`。

### 3.3 NAT 与状态防火墙：会话表是一切的基础

**解决什么问题**：NAT 解决了 IPv4 地址不足与内网隐藏；状态检测防火墙解决了「只按单包规则过滤会被绕过」的问题。两者的共同内核是**会话表（Session Table）**。

**NAT 四种类型对比**：

| 类型 | 映射方式 | 端口复用 | 典型用途 |
|---|---|---|---|
| 静态 NAT | 1 个内网 IP ↔ 1 个公网 IP | 否 | 对外的服务器发布 |
| 动态 NAT | 内网 IP 从公网地址池临时取一个 | 否 | 内网用户上网（池内一对一） |
| PAT / NAT 重载 | 多内网 IP 复用 1 个公网 IP | 是（按端口区分） | 家庭 / 企业出口最常见 |
| NAT 回流 | 内网访问「公网映射地址」时自动改写 | — | 内外网双域名场景 |

**PAT 会话表的键**是五元组：`(协议, 内网源IP, 内网源端口, 外网目的IP, 外网目的端口)`。转换后新增一列「公网映射端口」。

**PAT 端口复用上限推导**：

```
可用端口数 = 65535 - 1024 + 1 = 64512
```

单公网 IP 的理论并发会话上限就是 **64512** 条（实际操作系统中还会受内存、每主机端口上限、超时策略限制，实测常在 2~4 万）。

**状态检测防火墙的判定逻辑**：

1. 首包到达时查会话表，若无表项则按安全策略（源域 / 目的域 / 服务 / 应用）决定新建（建表）或丢弃。
2. 建表后，后续报文只要命中会话表就直接放行，**不再逐包查策略**，因此回程流量无需单独写规则。
3. 会话有超时时间（TCP 已建连常见 3600s / 长连接可达 24h；TCP 半开 30s；UDP 30s；ICMP 10s）。超时即回收，回包将因无表项被丢弃。

这就是「为什么从外网主动 ping 内网主机 ping 不通，但内网 ping 外网能收到回包」的根本原因。

### 3.4 IPsec VPN：IKE 两阶段与 ESP 封装

**解决什么问题**：在不可信的公共网络上建立加密隧道，把两个站点的内网连起来（站点到站点），或让员工远程接入（远程接入）。

**IKE（Internet Key Exchange）两阶段**：

- **阶段一（IKE SA）**：协商并建立一个管理隧道，产出 IKE SA。两种模式：
  - **主模式（Main Mode）**：6 个报文（3 次往返），身份保护更好，用于站点到站点。
  - **野蛮模式（Aggressive Mode）**：3 个报文，快但身份明文且易被离线爆破，仅在固定 IP 场景用。
- **阶段二（IPsec SA）**：在 IKE SA 保护下协商数据隧道参数（加密算法、哈希、封装模式、PFS），产出**成对**的 IPsec SA（每个方向一条）。

**AH 与 ESP**：

- **AH（Authentication Header）**：只做完整性与认证，**不加密**；校验范围覆盖外层 IP 头（含地址），因此**无法穿越 NAT**。
- **ESP（Encapsulating Security Payload）**：既加密又认证，校验范围不含外层 IP 头，**能穿 NAT**。生产环境几乎只用 ESP。

**ESP 报文结构**（本次演示的算法组合为 AES-128-CBC + HMAC-SHA1-96）：

```
隧道模式：
+------------+--------+--------+----------------------+--------+------+
| 新 IP 头   | ESP头  |  IV    |   加密载荷(原IP分组)  | 填充+尾| ICV  |
|   20 B     |  8 B   | 16 B   |   (...对齐16B...)    |  2 B+  | 12 B |
+------------+--------+--------+----------------------+--------+------+
                ^SPI 4B ^序号 4B

传输模式：
+------------+--------+--------+----------------------+--------+------+
| 原 IP 头   | ESP头  |  IV    |   加密载荷(传输层段)  | 填充+尾| ICV  |
|   20 B     |  8 B   | 16 B   |                      |        | 12 B |
+------------+--------+--------+----------------------+--------+------+
```

**填充对齐规则**：加密区长度 = 载荷 + 填充 + 尾部(1 字节填充长度 + 1 字节下一头部)，必须是分组长度 16 字节的整数倍。填充长度 `pad = align_up(payload + 2, 16) - payload - 2`。

### 3.5 常见攻击原理与特征

**ARP 欺骗**：ARP 协议本身无任何认证，主机收到 ARP 应答（哪怕没发过请求）也会直接更新缓存。攻击者向 PC1 发「网关 IP 对应我的 MAC」，向网关发「PC1 IP 对应我的 MAC」，即完成双向劫持。

**中间人（MITM）**：在 ARP 欺骗的基础上，攻击者打开 IP 转发做透明中转（保证受害者不断网），即可旁路读取明文、或对 TLS 做降级/伪造证书攻击。

**SYN Flood**：利用 TCP 三次握手第一步就分配半连接（SYN 队列）资源的特性，用伪造源 IP 发海量 SYN，撑满队列，真实用户的新 SYN 被丢弃。

**端口扫描**：五种常见类型——`TCP connect`（完整握手，会被目标记录）、`TCP SYN`（半开，不成三次握手）、`FIN`、`XMAS`（FIN+PSH+URG）、`NULL`（全 0 标志位）。后三种利用「关闭端口回 RST、开放端口忽略」来判定。

### 3.6 802.1X 与端口安全

**解决什么问题**：防止「网线一插就能上网」，把接入控制从「物理端口」提升到「身份认证」。

- **802.1X 三元组**：客户端（Supplicant）、交换机（Authenticator）、认证服务器（RADIUS）通过 **EAP over LAN（EAPOL）** 交互。认证前端口只放行 EAPOL，认证通过后按动态 VLAN 放行业务流量，认证失败进入 guest VLAN 或直接 shut。
- **端口安全（Port Security）**：限制端口可学习的源 MAC 数量（`maximum`）、绑定具体 MAC（`mac-address`）、违规动作（`protect / restrict / shutdown`）。
- **MAC 地址绑定 + 端口隔离**：同一 VLAN 内主机默认互通，用 `port-isolate` 或私有 VLAN 阻断同网段横向移动，防「一台中毒全网被扫」。

### 3.7 接入层防御三件套：DHCP Snooping + DAI + IPSG

三者是一条链，缺一环就会被绕过：

1. **DHCP Snooping**：把连接 DHCP 服务器的端口标记为「信任口（trusted）」，其余为非信任口。非信任口来的 DHCP Offer / ACK 一律丢弃，防止伪造 DHCP 服务器下发错误网关。同时生成 **DHCP Snooping 绑定表**：`MAC ↔ IP ↔ 端口 ↔ VLAN`。
2. **DAI（Dynamic ARP Inspection）**：用 DHCP Snooping 绑定表校验 ARP 报文，伪造的 ARP 应答直接丢弃。
3. **IP Source Guard（IPSG）**：用同一张绑定表校验 IP 报文的源地址，防止 IP 欺骗。

顺序上必须先有 DHCP Snooping 绑定表，DAI 和 IPSG 才有数据可查——所以「只开 DAI 不开 DHCP Snooping」是一条典型的空配置。

### 3.8 等保与网络分区

合规视角的核心是**分区**和**审计**：按业务重要性划分为核心区 / 汇聚区 / 接入区 / 隔离区（DMZ）/ 运维管理区，区间用防火墙做最小必要放通，跨区流量全量留存日志。技术落地为：安全域划分 + 访问控制 + 入侵防范 + 日志审计（Syslog/NetFlow 集中留存 ≥6 个月）+ 数据加密 + 备份恢复。

## 五、关键字段 / 报文格式解剖

### 5.1 扩展 ACL 规则字段

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| action | — | 命中后动作 | `permit` / `deny` |
| protocol | 1 字节（协议号） | 匹配的上层协议 | `ip`(任意) / `tcp`(6) / `udp`(17) / `icmp`(1) |
| source + wildcard | 8 字节 | 源地址与忽略位 | `192.0.2.0 0.0.0.255` |
| destination + wildcard | 8 字节 | 目的地址与忽略位 | `host 198.51.100.10`（等价 `0.0.0.0` 通配符） |
| source-port / dest-port | 2 字节 | TCP/UDP 端口过滤 | `eq 443` / `eq 23` / `range 1024 65535` |
| time-range（可选） | — | 规则生效时间段 | `WORK`（工作日 9:00-18:00） |

### 5.2 ESP 报文各字段

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| 新 IP 头（仅隧道模式） | 20 字节 | 承载 ESP 的外层头 | 协议号 50（ESP） |
| SPI | 4 字节 | 安全参数索引，标识 SA | 任意 32 位，两端各自约定 |
| 序号 Sequence | 4 字节 | 抗重放 | 每包 +1，起始 1 |
| IV | 8 / 16 字节 | 加密初始向量 | AES-CBC 16B，3DES 8B |
| 加密载荷 | 可变 | 被保护的数据 | 传输模式=段，隧道模式=整个原分组 |
| 填充 Padding | 0~255 字节 | 对齐到分组长度 | AES 对齐到 16 的倍数 |
| Pad Length | 1 字节 | 填充字节数 | 0 ~ 255 |
| Next Header | 1 字节 | 载荷类型 | 4(IP) / 6(TCP) / 17(UDP) |
| ICV | 12 / 16 字节 | 完整性校验 | SHA1-96 为 12B，SHA256-128 为 16B |

## 六、易混概念对比

| 概念 A | 概念 B | 核心区别 | 典型场景 |
|---|---|---|---|
| 标准 ACL | 扩展 ACL | 标准只能匹配源 IP；扩展可匹配协议+源目地址+端口 | 标准用于「限制管理源」，扩展用于接口精细化过滤 |
| 包过滤防火墙 | 状态检测防火墙 | 前者逐包独立判断，后者按会话表放行回程 | 包过滤已淘汰，现代设备默认状态检测 |
| NAT（一对一） | PAT（多对一） | NAT 不共享端口、PAT 用端口区分会话 | 服务器发布用 NAT，用户上网用 PAT |
| AH | ESP | AH 不加密且不能穿 NAT；ESP 加密且可穿 NAT | 生产几乎只用 ESP |
| 传输模式 | 隧道模式 | 前者不加外层 IP 头、内网地址明文；后者加密整个原分组 | 主机到主机用传输，站点到站点用隧道 |
| DAI | IPSG | DAI 校验 ARP 报文，IPSG 校验 IP 报文源地址 | 同一张 Snooping 绑定表，两者配合使用 |
| IDS | IPS | IDS 只告警不阻断（旁路），IPS 在线阻断 | IDS 用于监测，IPS 用于边界防御 |

## 七、工程实践与最佳实践

1. **ACL 顺序决定成败**，把「最具体、命中率最高」的规则放最前面。因为 ACL 命中即停，「permit ip any any」放在第一条会让后面所有 deny 全部失效。
2. **每个接口的 ACL 都要写显式兜底 deny**（如 `deny ip any any log`）。因为隐式 deny 不产生日志，出问题时你根本不知道是哪个包被丢了。
3. **ACL 变更必须在维护窗口做并先备份**。因为一条误删的 permit 会瞬间切断业务，且 ACL 是逐条顺序执行的，改一条可能影响后面所有规则。
4. **NAT 出口要监控端口占用率**。因为 PAT 单 IP 上限约 6.4 万条会话，出口汇聚比达到 1:100 时端口会在高峰期耗尽，表现为「网页打不开但 ping 得通」。
5. **长连接应用的 NAT 超时时间必须大于应用心跳周期**。因为 NAT 会话表默认 300s（TCP）超时，若应用 600s 才发一次心跳，中间会被静默掐断而不返回 RST。
6. **IPsec 两端必须严格匹配加密算法 / 哈希 / PFS / 封装模式**。因为任何一项不一致，IKE 阶段二协商失败，表现为 `Phase 2 未建立`，隧道 up 但业务不通。
7. **IPsec 隧道模式必须规划好 MTU**。因为外层 IP + ESP + IV + ICV 至少吃掉 50~73 字节，物理 1500 时内层 MTU 只能设 1400 左右，且要配合 `ip tcp adjust-mss`。
8. **接入端口先开 DHCP Snooping 再开 DAI / IPSG**。因为没有 Snooping 绑定表，DAI 会误杀正常 ARP，导致合法主机也上不了网。
9. **交换机非信任端口要关闭 DTP 并强制 Access 模式**。因为默认 DTP 会让攻击者协商成 Trunk，一步跳到所有 VLAN（VLAN Hopping）。
10. **核心交换机启用 uRPF（反向路径转发检查）**。因为 uRPF 能基于路由表丢弃源地址不可达的伪造报文，是抵御 IP 欺骗最划算的一道防线。
11. **管理面独立成带外或独立管理 VLAN，且只允许运维网段登录**。因为管理面一旦暴露在业务网，任何一台被控主机都能横向登录设备。
12. **日志必须集中留存并设置基线告警**。因为单机日志会被刷掉，只有集中 + 基线才能发现「某个端口扫描」「某源 IP 大量被拒」这类攻击前兆。

## 八、常见陷阱清单

| # | 现象 | 根因 | 排查 / 规避 |
|---|------|------|-------------|
| 1 | ACL 里明明写了 permit，业务还是不通 | 前面有条 deny 提前命中（ACL 命中即停） | 用 `show ip access-lists 100` 看每条规则的匹配计数，定位真实命中项 |
| 2 | 「只写了 permit」结果其余全断 | 每条 ACL 末尾隐含 `deny any` | 明确写出兜底规则，并加 `log` 便于观察 |
| 3 | 通配符写成子网掩码导致规则范围错 | 把 `0.0.0.255` 误写成 `255.255.255.0` | 记牢：通配符 0=必须匹配、1=忽略；`host`=0.0.0.0，`any`=255.255.255.255 |
| 4 | 内网能 ping 外网，外网 ping 不进内网 | NAT / 状态防火墙无入向会话 | 这是正常设计，需要发布就配置静态端口映射 |
| 5 | 高峰期网页打不开但 ping 正常 | NAT 端口池耗尽或会话表满 | 监控 PAT 端口占用，扩容公网 IP 或做多出口 |
| 6 | 长连接每 5 分钟断一次 | NAT 会话超时（默认 300s）早于应用心跳 | 把对应协议的 NAT 超时调大，或缩短应用心跳 |
| 7 | IPsec 隧道 up 但大包不通 | ESP 封装后超过物理 MTU，且 DF=1 | 调低内层 MTU + `ip tcp adjust-mss 1360`，并开启 PMTUD |
| 8 | IPsec 阶段一成功、阶段二失败 | 两端 ACL / 加密 / PFS 参数不一致 | 比对 `show crypto ipsec sa` 与对端配置，重点看 ACL 是否镜像 |
| 9 | 开了 DAI 之后全楼上不了网 | 没有 DHCP Snooping 绑定表，正常 ARP 被误杀 | 先开 DHCP Snooping 生成绑定表，再开 DAI；静态 IP 主机要手工建绑定 |
| 10 | 接入端口协商成 Trunk，VLAN 被跳 | 默认启用 DTP 且未强制 Access | 接入口配 `switchport mode access` + `switchport nonegotiate` |
| 11 | 某台主机 ARP 表里网关 MAC 频繁变化 | 局域网存在 ARP 欺骗 | 抓包看同一 MAC 映射多个 IP，开 DAI，检查是否有人私接 |
| 12 | 服务器被大量半开连接拖垮 | SYN Flood 打满半连接队列 | 开 SYN Cookie，观察 `netstat -s` 的 SYN 重传计数 |
| 13 | 防火墙有大量 deny 日志来自同一源 | 端口扫描 / 暴力探测 | 对该源做速率限制与封禁，核查是否内网已被控做跳板 |
| 14 | IPsec 远程接入用户多但带宽上不去 | 加密性能瓶颈在设备 CPU 而非链路 | 看设备 CPU 与加密吞吐指标，必要时上专用加密卡或利旧网关 |
| 15 | 换了主备 NAT 设备后会话全断 | NAT 会话表未同步 | 部署支持会话同步的主备方案，并开启会话热备份 |

## 九、自测练习

1. 判断命中：ACL 规则 `permit ip 192.0.2.0 0.0.0.127 any`，报文源地址 `192.0.2.100`，是否命中？
2. 计算通配符：写出 `172.16.0.0/20` 对应的点分掩码与通配符掩码。
3. 计算 PAT 上限：出口有 2 个公网 IP，端口池 1024~65535，理论最大并发会话数是多少？
4. 计算 ESP 开销：内层 UDP 报文（IP 20 + UDP 8 + 数据 100）走隧道模式 ESP（AES-CBC + SHA1-96），求封装后总长度。
5. 排障：某接口只配了 `permit tcp any any eq 443`，结果 ICMP 全部不通，为什么？
6. 排障：IPsec 站点到站点隧道显示 up，但内网 PC 之间访问大文件卡死、小 ping 正常，怎么定位？
7. 计算：DHCP Snooping 绑定表校验中，某 ARP 报文源 MAC 为 `02:00:00:00:00:0A`、源 IP 为 `192.0.2.50`，绑定表记录该端口对应 `02:00:00:00:00:0B ↔ 192.0.2.50`，DAI 如何判定？
8. 解释为什么扩展 ACL 能匹配端口而标准 ACL 不能。
9. 说明「只开 DAI 不开 DHCP Snooping」会发生什么。
10. 简述 SYN Cookie 如何在不分配半连接资源的前提下完成正常握手。

<details>
<summary>参考答案</summary>

**1.** 逐位比对。

- 通配符 `0.0.0.127` 表示前 25 位必须匹配、后 7 位忽略（`127 = 0111 1111`，即最后 7 位忽略）。
- 规则地址 `192.0.2.0` 的网络位 = `192.0.2.0`；报文 `192.0.2.100` 的前 25 位 = `192.0.2.0`。
- 代入公式：`(0xC0000264 XOR 0xC0000200) AND NOT 0x0000007F`。
  `0xC0000264 XOR 0xC0000200 = 0x00000064`；`NOT 0x0000007F = 0xFFFFFF80`。
  `0x64 AND 0xFFFFFF80 = 0x00000000`。
- 结果 0，**命中**。

**2.** `/20` 表示前 20 位为网络位。

- 点分掩码：前 20 位为 1 = `11111111.11111111.11110000.00000000` = `255.255.240.0`。
- 通配符 = NOT 掩码 = `00000000.00000000.00001111.11111111` = `0.0.15.255`。
- 验证：`240 + 15 = 255`，末段 `0 + 255 = 255`，成立。

**3.** 每个公网 IP 的可用端口数：

```
65535 - 1024 + 1 = 64512（个端口）
```

2 个公网 IP：

```
总上限 = 64512 × 2 = 129024（条约 12.9 万条）
```

单位说明：这是理论端口上限；考虑内存与超时策略，工程上按 50%~70% 预留，即约 6.5~9 万条可安全承载。

**4.** 隧道模式封装。

- 原分组长度 `inner = 20 + 8 + 100 = 128` 字节。
- 加密前载荷 `payload = 128`，尾部固定 2 字节（填充长度 + 下一头部）。
- 对齐到 16 字节：`align_up(128 + 2, 16) = align_up(130, 16) = 144`（144/16 = 9）。
- 填充 `pad = 144 - 128 - 2 = 14` 字节。
- 开销 = 外层 IP 20 + ESP 头 8 + IV 16 + 填充 14 + 尾部 2 + ICV 12 = **72 字节**。
- 封装后总长度 = 128 + 72 = **200 字节**。

**5.** 因为 ACL 末尾隐含 `deny any`。

该规则只 permit 了 TCP 443，ICMP 协议不匹配任何显式规则，落到隐式 deny。修法：可以 `permit icmp` 显式放通，或把规则写成 `permit ip any any`（按需）。

**6.** 典型 MTU 黑洞。

- 现象：小包（ping，64B）能过，大包（下载，>1400B）被丢且 DF=1 时无 ICMP 分片需求回落，TCP 卡死。
- 定位：两端 `ping -l 1500 -f`（Cisco）或在主机上 `ping -M do -s 1472`，逐级缩小包发现 1400 左右断裂；`show crypto ipsec sa` 看是否分片/丢弃计数增长。
- 处理：隧道接口设 `ip mtu 1400`，同时 `ip tcp adjust-mss 1360`，让 TCP 主动缩小 MSS。

**7.** DAI 判定依据绑定表的 MAC↔IP 双向一致。

- 绑定表该端口记录 `MAC = 02:00:00:00:00:0B`、`IP = 192.0.2.50`。
- 报文的源 MAC 是 `02:00:00:00:00:0A`，与绑定表不符。
- **判定：丢弃该 ARP 报文**（典型 ARP 欺骗特征：IP 对得上但 MAC 对不上）。

**8.** 因为匹配需要读取的信息层级不同。

标准 ACL 只看 IP 首部的**源地址**字段，无需解析传输层；扩展 ACL 会进一步解析 IP 首部的**协议号**字段，再按 TCP/UDP 首部读取**源端口 / 目的端口**（各 2 字节）。由于端口字段只存在于传输层，标准 ACL 在信息上就不具备匹配端口的能力。

**9.** DAI 会失去校验依据并误杀正常流量。

在没有 DHCP Snooping 绑定表的接口上，DAI 的默认行为对非信任口是「无绑定表即丢弃」，因此正常主机的 ARP 也会被丢，表现为整个网段二层不通、无法解析网关 MAC。正确顺序是先开 DHCP Snooping 生成绑定表，静态 IP 主机需手工补静态绑定。

**10.** SYN Cookie 把连接状态编码进序列号，不落表。

1. 收到 SYN 时，服务器不分配半连接资源，而是用 `(源IP, 源端口, 目的IP, 目的端口, 时间戳, 随机数)` 经哈希（结合服务端密钥）算出一个初始序列号 `ISN`。
2. 用该 `ISN` 回 SYN-ACK，把状态「记在」序列号里，服务器本地不保存任何连接记录。
3. 若客户端真实存在，会回 ACK，其`确认号 = ISN + 1`；服务器用同样输入重算哈希，比对确认号是否合法。
4. 校验通过才真正建连接。伪造源 IP 的客户端收不到 SYN-ACK，自然无法回正确 ACK，攻击流量就白费了。

</details>
