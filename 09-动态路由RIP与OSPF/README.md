# 第 09 章 · 动态路由 RIP 与 OSPF

> **一句话定位**：让路由器自己「学会」网络拓扑 —— 讲清距离矢量（RIP）与链路状态（OSPF）两套完全不同的思维方式，读完能手工算 OSPF Cost、跑 Dijkstra、看懂邻居卡在哪个状态、判断 RIP 为什么慢。
> **前置知识**：第 08 章（路由表与静态路由） ｜ **难度**：★★★ ｜ **建议投入**：150 分钟

## 一、学习目标

1. 能按「距离矢量 / 链路状态 / 路径矢量」三分法给任意路由协议归类，并说明三者的信息交换对象与收敛特点。
2. 能默写 RIP 的四个计时器取值（30s / 180s / 240s / 180s 抑制）与「15 跳不可达」的边界，并解释计数到无穷的成因。
3. 能算出任意接口在任意参考带宽下的 OSPF Cost，并说明为什么默认参考带宽 100Mbps 会把千兆和万兆「抹平」。
4. 能画出 OSPF 邻居 7 状态迁移图，并说出卡在 Init、ExStart、Exchange、Loading 各自对应的根因。
5. 能区分 LSA Type 1/2/3/4/5/7 的生成者、作用域与用途，并说明 Stub / NSSA 区域会屏蔽哪些 LSA。
6. 能给定一张广播网拓扑，按接口优先级与 Router-ID 手工选出 DR/BDR。

## 二、核心概念总览

```
                        动态路由协议
        ┌──────────────────┬──────────────────┬──────────────────┐
        │ 距离矢量          │ 链路状态          │ 路径矢量          │
        │ Distance Vector   │ Link State        │ Path Vector       │
        ├──────────────────┼──────────────────┼──────────────────┤
        │ RIP、IGRP         │ OSPF、IS-IS       │ BGP               │
        │ 只把「整张路由表」 │ 只把「自己的链路」 │ 只把「AS 跳序列」 │
        │ 说给邻居听         │ 泛洪给所有人       │ 说给对等体        │
        │ 贝尔曼-福特        │ Dijkstra(SPF)     │ 逐跳比较属性      │
        │ 传闻式、易环       │ 全局图、无环       │ 策略驱动          │
        └──────────────────┴──────────────────┴──────────────────┘
```

三块的关系是：**RIP 是「听邻居说」，OSPF 是「自己算图」，BGP 是「按策略挑路」**。RIP 收敛慢但配置简单，适合小网络；OSPF 收敛快、支持分级区域，是企业网主力；BGP 不管快慢，只管在多个运营商之间按策略选路。本章把前三块里的前两块讲透，路径矢量留到第 10 章。

## 三、机制详解

### 3.1 距离矢量：把自己知道的整张表交给邻居

距离矢量的核心是一句话：**我不知道全网长什么样，我只知道「去某个网段要几跳、下一跳是谁」，邻居告诉我他几跳，我就加一跳**。这条规则叫贝尔曼-福特（Bellman-Ford）方程：`d(x) = min{ cost(v,x) + d(v) }`，其中 v 遍历所有邻居。

它的致命弱点是**坏消息传得慢**。R1 直连网段 192.0.2.0/24（开销 0），R2 从 R1 学到（开销 1）。当 R1 的直连链路断开：

1. R1 把 192.0.2.0/24 置为 16（不可达）。
2. 但 R2 的更新还没到，R2 仍对外通告「我 1 跳可达」。
3. R1 听到 R2 的通告，重新认为「经 R2 2 跳可达」，于是通告 2。
4. R2 听到 R1 的 2，改成 3，通告 3；R1 改成 4……双方互指，度量一路涨到 16。

这就是**计数到无穷（count to infinity）**。RIP 用 15 跳不可达把「无穷」压到一个有限值，再靠下面三种机制压制环路：

- **水平分割（Split Horizon）**：从某接口学到的路由，不再从这个接口说回去。
- **毒性逆转（Poison Reverse）**：从某接口学到的路由，说回去时度量直接写 16，比「沉默」更明确。
- **触发更新（Triggered Update）**：拓扑一变化立刻发，不等 30 秒周期。
- **抑制计时器（Holddown）**：收到某网段的不可达消息后，180 秒内不再接受任何关于它的更新，避免被旧的好消息「翻回去」。

### 3.2 RIP：报文、计时器与 v1/v2 差异

RIP 跑在 **UDP 520** 端口上，一条报文最多带 25 个路由条目，每条 20 字节（地址族 2B + 路由标记 2B + 网段 4B + 掩码 4B + 下一跳 4B + 度量 4B）。四个计时器必须记牢：

| 计时器 | 默认值 | 作用 |
|---|---|---|
| Update（更新） | 30 秒 | 周期性地把整张路由表向外通告 |
| Invalid / Timeout（超时） | 180 秒 | 超过此时间没收到该路由更新，标记为 16（不可达） |
| Holddown（抑制） | 180 秒 | 收到不可达后，此窗口内忽略关于该网段的更优更新 |
| Flush（刷新） | 240 秒 | 从路由表彻底删除该条目 |

v1 与 v2 的关键差异：

| 对比项 | RIPv1 | RIPv2 |
|---|---|---|
| 发送方式 | 广播 255.255.255.255 | 组播 224.0.0.9 |
| 掩码 | 不携带掩码，按 A/B/C 类推断（有类） | 携带掩码，支持 VLSM/CIDR（无类） |
| 认证 | 无 | 明文 / MD5 |
| 下一跳 | 无此字段 | 有 Next Hop 字段，可指定绕行 |
| 路由标记 | 无 | 有 Route Tag，用于与外部协议互通 |

在思科设备上 `show ip protocols` 能看到 `Sending updates every 30 seconds, next due in 12 seconds`，在华为上是 `display rip 1` 显示 `Periodic timer: 30`。

### 3.3 OSPF 的思维方式：每台路由器都拿着一张全网地图

OSPF 不交换路由表，而是交换**链路状态（Link State）**：每台路由器描述「我有哪些接口、连了谁、每条链路开销多少」，这些描述被打包成 **LSA（Link State Advertisement）**，在区域内泛洪。最终每台路由器收集到**完全相同的链路状态数据库（Link State Database, LSDB）**，再各自跑一次 **Dijkstra 最短路径优先（Shortest Path First, SPF）** 算法，得到以自己为根、无环的最短路径树。

OSPF 直接封装在 **IP 协议号 89** 上（不用 TCP/UDP）。邻居建立条件（缺一不可）：

1. 双方接口在同一区域（Area ID 一致）。
2. 接口掩码一致（点对点链路除外）。
3. HelloInterval 与 DeadInterval 一致（广播网默认 10s / 40s，Dead = 4 × Hello）。
4. 认证类型与密钥一致。
5. MTU 一致（影响 ExStart / Exchange 阶段的 DBD 协商）。
6. 双方 Router-ID 不能相同。
7. 网络类型匹配（广播 / 点对点 / NBMA 等）。

**Router-ID 的选取顺序**：手工 `router-id` 命令指定 > 最大的环回接口 IP > 最大的物理接口 IP。工程上一定要手工指定，否则接口抖动可能改变 Router-ID 引发邻居重建。

### 3.4 邻居 7 状态与 LSA 作用域

```
Down ──收到Hello──> Init ──看到我在邻居列表──> 2-Way ──DR选举完成──> ExStart
                                                                     │
                                                              协商Master/Slave
                                                                     ↓
Full <────LSDB同步──── Loading <──LSR/LSU/LSAck── Exchange <─────────┘
```

- **2-Way** 是 DR 选举的完成点：DROther 之间停在这里不再往上走，只与 DR/BDR 建立 Full。
- **ExStart** 用空的 DBD 比 Router-ID 决定主从；**两端 MTU 不一致会在这里反复翻转**。
- **Exchange** 互发 DBD 摘要；**Loading** 用 LSR/LSU 补齐差异；**Full** 表示 LSDB 完全一致。

LSA 按作用域分五层（Type 6 为组播扩展，现网基本不用）：

| 类型 | 名称 | 生成者 | 作用域 | 用途 |
|---|---|---|---|---|
| Type 1 | Router-LSA | 每台路由器 | 本区域 | 描述自身链路，SPF 的输入 |
| Type 2 | Network-LSA | 广播网的 DR | 本区域 | 代表多路访问网段的伪节点 |
| Type 3 | Summary-LSA | ABR | 跨区域 | 把一个区域的网段汇总播给其它区域 |
| Type 4 | ASBR-Summary-LSA | ABR | 跨区域 | 告诉其它区域 ASBR 在哪 |
| Type 5 | AS-External-LSA | ASBR | 整个 AS | 引入外部路由（E1/E2） |
| Type 7 | NSSA-External-LSA | NSSA 内的 ASBR | 只在 NSSA | NSSA 内引入外部路由，ABR 翻译成 Type 5 |

### 3.5 Cost 与 SPF 计算

**Cost 公式**：`Cost = 参考带宽 / 接口带宽`，结果**向下取整，最小为 1**。默认参考带宽 **100 Mbps**。代入：

- 10M 接口：`100 / 10 = 10`
- 100M 接口：`100 / 100 = 1`
- 1G 接口：`100 / 1000 = 0.1 → 取整 0 → 因下限取 1`
- 10G 接口：`100 / 10000 = 0.01 → 取 1`

也就是说默认配置下 **100M / 1G / 10G 的 Cost 全是 1**，带宽差异被完全抹平。要区分，必须把参考带宽改大并**全网统一**：

- 思科：`router ospf 1` → `auto-cost reference-bandwidth 10000`（单位 Mbps，即 10G）
- 华为：`ospf 1` → `bandwidth-reference 10000`

改成 10G 后：1G = 10，10G = 1。若还想区分 10G 与 100G，得再把参考带宽提到 100G。

SPF 即 Dijkstra，步骤：

1. 把根节点距离置 0，其余置无穷，全部标记为「未固化」。
2. 在未固化节点中挑距离最小者，固化为「已确定」。
3. 松弛它的所有邻居：若 `dist[u] + w(u,v) < dist[v]`，更新 `dist[v]` 并把 `prev[v]` 记成 u。
4. 重复 2~3，直到所有可达节点被固化。
5. 按 `prev` 回溯出到每个目的网段的下一跳。

### 3.6 区域设计与路由汇总

OSPF 用区域（Area）做两级分层：**骨干区域 Area 0（0.0.0.0）** 必须在中心，所有非骨干区域都得直接或通过虚链路（Virtual Link）连到 Area 0。这样区域内拓扑变化只在区域内泛洪，不会让整个 AS 重算 SPF。

- **ABR（Area Border Router）**：同时属于多个区域，负责产生 Type 3/4 与做区域间汇总。
- **ASBR（AS Autonomous System Boundary Router）**：引入外部路由，产生 Type 5。
- **Stub 区域**：不允许 Type 5 进入，出口只能靠一条默认路由。省内存、缩小 LSDB。
- **Totally Stub（完全末梢）**：连 Type 3 也只留一条默认路由，比 Stub 更彻底。
- **NSSA（Not-So-Stubby Area）**：既要精简，又需要引入少量外部路由，于是用 Type 7 在内部表达，到 ABR 再翻译成 Type 5。

区域间汇总用 `area 1 range 10.1.0.0 255.255.0.0`（思科）/ `abr-summary 10.1.0.0 255.255.0.0`（华为），外部路由汇总用 `summary-address`（思科）/ `asbr-summary`（华为）。

### 3.7 RIP 与 OSPF 选型对比

| 对比项 | RIP | OSPF |
|---|---|---|
| 算法 | 距离矢量（贝尔曼-福特） | 链路状态（Dijkstra） |
| 度量 | 跳数（最大 15） | Cost（累加链路开销） |
| 收敛 | 慢（分钟级） | 快（秒级，可做到亚秒） |
| 规模 | 小（≤15 跳，几十台） | 大（支持区域分层，上千台） |
| 协议承载 | UDP 520 | IP 协议号 89 |
| 负载分担 | 仅等价跳数 | 支持 ECMP（等价 Cost） |
| 分级 | 无 | Area 0 + 非骨干区域 |
| 适用 | 小型分支、备线、实验 | 企业骨干、数据中心 |

## 四、动手验证

### 4.1 `rip_convergence.py` —— 看见「计数到无穷」

演示 4 节点链 R1-R2-R3-R4（目的网段 192.0.2.0/24 直连 R3），逐轮打印每个节点持有的 (度量, 下一跳)，对比三种机制。

```
运行: python3 rip_convergence.py
```

关键输出：

```
场景：无防环（裸距离矢量）
阶段      R1(经)      R2(经)      R3(经)      R4(经)
故障后    2(R2)       1(R3)       不可达(-)   1(R3)
第 1 轮   2(R2)       3(R1)       不可达(-)   不可达(-)
第 2 轮   4(R2)       3(R1)       不可达(-)   不可达(-)
   ...
第 14 轮  不可达(-)   15(R1)      不可达(-)   不可达(-)
>>> 结论：全部节点达成「不可达」用时 15 轮；过程中出现的最大有限度量为 15
```

从输出能看出：裸距离矢量下 R1 与 R2 互相引用过期路由，度量 2→3→…→15 一路涨。而水平分割与毒性逆转下最大有限度量只有 2，2 轮即收敛。

## 五、关键字段 / 报文格式解剖

### 5.1 OSPF 公共头（24 字节，五种报文共用）

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| Version | 1 字节 | 版本号 | IPv4 用 2，IPv6 用 3 |
| Type | 1 字节 | 报文类型 | 1=Hello 2=DBD 3=LSR 4=LSU 5=LSAck |
| Packet Length | 2 字节 | 整包长度（含 24B 头） | 依报文而定 |
| Router ID | 4 字节 | 发送者 Router-ID | 如 203.0.113.1 |
| Area ID | 4 字节 | 区域号 | 骨干区为 0.0.0.0 |
| Checksum | 2 字节 | 校验和（不含 IP 头） | 标准 IP 式校验 |
| AuType | 2 字节 | 认证类型 | 0=无 1=明文 2=MD5 |
| Authentication | 8 字节 | 认证数据 | 明文/MD5 摘要 |

### 5.2 OSPF Hello 报文关键字段

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| Network Mask | 4 字节 | 接口掩码，不一致不建邻接 | 255.255.255.0 |
| HelloInterval | 2 字节 | Hello 周期 | 10s（广播）/ 30s（NBMA） |
| Options | 1 字节 | 能力位 E/N/DC | E=1 表示可处理 Type 5 |
| Rtr Pri | 1 字节 | 接口优先级 | 0~255，默认 1，0=不参选 |
| DeadInterval | 4 字节 | 判死时间 | 40s = 4 × HelloInterval |
| DR / BDR | 4+4 字节 | 发送者眼中的 DR/BDR | 接口 IP 或 0.0.0.0 |
| Neighbor | 变长 | 已双向可见的邻居列表 | 有无我 = Init 与 2-Way 分界 |

### 5.3 RIP v2 报文条目（每条 20 字节）

| 字段 | 长度 | 作用 | 常见取值 |
|---|---|---|---|
| Address Family | 2 字节 | 地址族 | 2 = IP |
| Route Tag | 2 字节 | 路由标记 | 用于与外部协议互通 |
| IP Address | 4 字节 | 目的网段 | 192.0.2.0 |
| Subnet Mask | 4 字节 | 掩码（v2 新增） | 255.255.255.0 |
| Next Hop | 4 字节 | 通告的下一跳（v2 新增） | 0.0.0.0 表示用发送者地址 |
| Metric | 4 字节 | 跳数 | 1~15，16 = 不可达 |

## 六、易混概念对比

| 概念 A | 概念 B | 核心区别 | 典型场景 |
|---|---|---|---|
| 距离矢量 | 链路状态 | 前者只交换路由表、靠传闻；后者泛洪链路描述、各自算图 | RIP vs OSPF |
| 水平分割 | 毒性逆转 | 前者「不说回去」，后者「说回去但写 16」 | 都用于 RIP 防环 |
| ABR | ASBR | ABR 连接多个区域产生 Type 3/4；ASBR 引入外部路由产生 Type 5 | 区域边界 vs AS 边界 |
| Stub 区域 | NSSA | Stub 拒绝 Type 5；NSSA 用 Type 7 在内部表达外部路由 | 精简 LSDB 的两种做法 |
| Type 3 | Type 5 | Type 3 是区域内网段（汇总）；Type 5 是外部引入路由 | 跨区 vs 引入 |
| 邻居（Neighbor） | 邻接（Adjacency） | 邻居只需 Hello 双向可见（2-Way）；邻接必须 LSDB 同步（Full） | DROther 之间只是邻居 |

## 七、工程实践与最佳实践

1. **OSPF 一定要手工指定 Router-ID**（`router-id 203.0.113.1`）。原因：靠环回/接口 IP 自动选取时，接口抖动会让 Router-ID 变化，触发邻居重建与全网 SPF 重算。
2. **上生产前把参考带宽统一改成实际最大带宽量级**。原因：默认 100Mbps 下 100M/1G/10G 的 Cost 都是 1，SPF 无法区分优劣，流量会走错链路。
3. **参考带宽必须全网一致**。原因：两端算法不一致会导致同一条链路两侧 Cost 不同，出现非对称路由，排障时「去程正常、回程绕路」极其难查。
4. **Area 0 必须连续**。原因：OSPF 规定非骨干区域之间的跨区流量必须经过 Area 0，Area 0 被割裂时区域间路由直接失效。
5. **单区域路由器数量控制在 50 台以内，超过就划区**。原因：单区域内每台路由器都要维护全网 Type 1/2 并跑全量 SPF，规模越大收敛越慢。
6. **区分点对点与广播网络类型**。原因：点对点不选 DR/BDR，若错配成广播会导致两端对 DR 的认知不一致，邻居停在 2-Way 或 ExStart。
7. **分支接入优先用 Stub / NSSA 精简 LSDB**。原因：减少 LSA 泛洪量，降低低端设备内存与 CPU 压力。
8. **RIP 只用在 15 跳以内的小网络或备线**。原因：跳数度量不反映带宽，且收敛慢，大网里会持续引发环路与黑洞。
9. **路由汇总只在 ABR/ASBR 上做**。原因：汇总点必须掌握完整明细才能安全聚合，在普通路由器上做会丢失明细导致黑洞。
10. **改动 OSPF 前先备份配置并选低峰期**。原因：`clear ip ospf process` / `reset ospf process` 会重建全部邻居，瞬断几秒到几十秒。
11. **给 OSPF 接口配认证**。原因：明文/无认证的 Hello 会被伪造，攻击者可注入假邻居导致路由被篡改。
12. **监控邻居状态与 SPF 触发次数**。原因：邻居频繁 Flapping 或 SPF 高频重算，往往是链路质量或 MTU 不匹配的前兆。

## 八、常见陷阱清单

| # | 现象 | 根因 | 排查 / 规避 |
|---|------|------|-------------|
| 1 | OSPF 邻居长期停在 Init | 只有一端能收到 Hello，单向可达；或一端配了认证另一端没配 | 双向 `ping`、`display ospf peer` 看是否互见；核对认证配置 |
| 2 | 邻居卡在 ExStart/Exchange 反复翻转 | 两端接口 MTU 不一致，DBD 协商失败 | `display interface` 比对 MTU，统一为 1500 或改小 |
| 3 | 邻居卡在 Exchange 不前进 | 对端有本端不认识的 LSA，或 LSDB 校验失败 | 重启邻居进程、检查是否有异常注入的 LSA |
| 4 | 邻居长期 Loading | LSR/LSU 有去无回，链路上有 ACL 丢了某类报文 | 检查 ACL 是否放行协议号 89 |
| 5 | 邻居能起但学不到路由 | 接口未宣告进区域，或宣告了错误的网络/掩码 | `display ospf interface` 确认接口是否在区域内 |
| 6 | 换链路后流量仍走老路 | 默认参考带宽下两条链路 Cost 都是 1，SPF 无差别 | 统一调大参考带宽，拉开 Cost 差异 |
| 7 | 非对称路由（去回程不同） | 只有一端改了参考带宽或某侧汇总不一致 | 全网核对 `bandwidth-reference` 与汇总配置 |
| 8 | DR 被「意料之外」的路由器占住 | DR 不可抢占，早期上线的高优先级设备一直当着 | 明确规划优先级；必要时手动 reset 强制重选 |
| 9 | 优先级 0 的接口仍出现在 DR 位置 | 该接口从没参与选举，是之前遗留的 DR 状态 | 改优先级后需 reset 进程才生效 |
| 10 | RIP 网络在链路故障后长时间不通 | 计数到无穷，度量慢慢爬到 16，期间形成环路 | 开启水平分割 + 毒性逆转 + 触发更新 |
| 11 | RIPv2 学到的掩码不对 | 对端误配成 v1（有类）发送，掩码被类推断 | 两端都显式 `version 2` |
| 12 | 区域间路由突然消失 | Area 0 在某处被割裂，或 ABR 的 Area 0 接口 down | 检查 Area 0 连续性；确认 ABR 至少一个接口在 Area 0 |
| 13 | 汇总后出现黑洞 | 汇总范围内有网段实际归其它路由器，明细未达 | 汇总前确认所有明细都在本区域且下一跳一致 |
| 14 | 引入外部路由后全网 LSDB 暴涨 | ASBR 未做聚合就往全域注入大量 Type 5 | 在 ASBR 上做 `summary-address` 聚合 |
| 15 | 更改 HelloInterval 后邻居全断 | 只改了单侧，确认参数不匹配导致 Hello 被丢弃 | 参数必须两端同步修改 |

## 九、自测练习

1. 一条 R1-R2-R3 链路，R3 直连 198.51.100.0/24，R1、R2 分别从 R3 学到的 RIP 度量是多少？
2. **计算题**：某 OSPF 网络参考带宽为默认 100 Mbps，路径 A 由三段 1G 链路组成，路径 B 由两段 100M 加一段 10G 组成，SPF 会选哪条？
3. **计算题**：把参考带宽改为 10 Gbps（`reference-bandwidth 10000`），重算上一题，结论是否改变？
4. **计算题**：一台路由器的 4 个接口带宽分别为 10M、100M、1G、10G，参考带宽 100M 时各 Cost 是多少？改成 10G 后呢？
5. 为什么 OSPF 邻居要到 2-Way 才能完成 DR 选举，而 DROther 之间停在 2-Way 不上 Full？
6. **排障题**：两台路由器直连，`display ospf peer` 显示邻居停在 `Init`，请给出至少三条可能原因与验证方法。
7. **排障题**：两台路由器邻居能到 Full，但路由表里没有对方宣告的网段，怎么查？
8. 为什么 Area 0 必须连续？如果不连续有哪些补救手段？
9. Type 3 与 Type 5 的生成者、作用域、触发条件分别是什么？
10. NSSA 区域为什么要引入 Type 7，而不是直接让 Type 5 进入？
11. **计算题**：某广播网有 8 台路由器，若不做 DR 选举，两两建立邻接需要多少条邻接关系？做了 DR/BDR 选举后呢？
12. RIP 的 180s 抑制计时器解决了什么问题，又带来了什么副作用？

<details>
<summary>参考答案</summary>

1. R3 直连度量 0；R2 为 1；R1 为 2。RIP 度量是「到目的网段的跳数」，由近及远每过一跳加 1。

2. 路径 A：三段 1G，默认参考带宽 100M 下每段 Cost = `100 // 1000 = 0 → 取 1`，合计 `1 + 1 + 1 = 3`。路径 B：两段 100M 各 Cost `100 // 100 = 1`，一段 10G Cost `100 // 10000 = 0 → 取 1`，合计 `1 + 1 + 1 = 3`。**两条路径 Cost 相同，SPF 会做等价负载分担（ECMP）**，这正说明默认参考带宽把带宽差异抹平了。

3. 参考带宽改为 10000（10G）后：路径 A 三段 1G 各 Cost = `10000 // 1000 = 10`，合计 `10 × 3 = 30`。路径 B：两段 100M 各 Cost = `10000 // 100 = 100`，一段 10G Cost = `10000 // 10000 = 1`，合计 `100 + 100 + 1 = 201`。`30 < 201`，**SPF 选路径 A**。结论改变 —— 参数一改，选路结果可能完全反转。

4. 参考 100M：10M → `100 // 10 = 10`；100M → `100 // 100 = 1`；1G → `100 // 1000 = 0 → 1`；10G → `100 // 10000 = 0 → 1`。参考 10G（10000）：10M → `10000 // 10 = 1000`；100M → `10000 // 100 = 100`；1G → `10000 // 1000 = 10`；10G → `10000 // 10000 = 1`。可见只有把参考带宽提到不小于最高接口带宽，层次才拉得开。

5. DR 选举信息承载在 Hello 报文中（DR/BDR 字段），而「对端是否已双向可见」要到 2-Way 才确定 —— 只有确认双向可见的邻居才有投票与被投票资格。DROther 之间不需要交换 LSDB：Type 2 LSA 由 DR 统一代表网段产生，DROther 只要与 DR/BDR 同步即可得到完整区域拓扑，因此它们停在 2-Way 是正常稳态。

6. 停在 Init 说明「能收到对方 Hello，但对方 Hello 里没有我的 Router-ID」。可能原因：① 单向可达（本端能收、对端收不到我的 Hello），可用双向 `ping` 与两端抓包确认；② 对端配置了 ACL 只放行部分 OSPF 报文；③ 一端配了认证另一端没配，我的 Hello 被对端丢弃，故对端邻居列表里没有我；④ 两端 Router-ID 冲突。验证：`display ospf peer` 看双向状态、`display ospf error` 看丢包计数、`display current-configuration interface` 比对认证与 ACL。

7. 邻居 Full 只代表 LSDB 同步，不代表接口被宣告进区域。查：① `display ospf interface` 确认本端接口是否已在目标区域（有无该接口的 Area）；② 检查 `network` 语句/`ospf enable` 是否覆盖了该网段与掩码；③ 若是 Type 3/5，检查 ABR/ASBR 是否做了过滤（`filter-policy`/`distribute-list`）；④ 检查是否被汇总吞掉或落到黑洞路由。

8. OSPF 规定区域间（Type 3）路由必须经骨干区 Area 0 中转，ABR 只把本区域网段注入 Area 0，再从 Area 0 分发到其它区域；Area 0 一旦被割裂，两个片区之间没有公共的骨干，跨区路由无法计算。补救手段：① 调整物理/逻辑拓扑让 Area 0 连续；② 用虚链路（Virtual Link）把断裂的 Area 0 桥接起来（需经过一个中转区域）；③ 重新规划区域。

9. Type 3（Summary-LSA）由 ABR 产生，作用域是跨区域（除 Totally-Stub），触发条件是 ABR 在本区域内学到网段后向其它区域通告。Type 5（AS-External-LSA）由 ASBR 产生，作用域是整个 AS（Stub/NSSA 除外），触发条件是把 OSPF 域外的路由（静态、RIP、BGP 等）引入 OSPF。

10. NSSA 的定位是「末梢区域」：不允许 Type 5 进入，从而精简 LSDB。但这类区域又可能需要引入少量外部路由（例如一条去外网的静态路由）。若直接放 Type 5 进来，就破坏了末梢语义，且会导致区域外 LSA 大量涌入。于是 OSPF 定义了 Type 7：它只在 NSSA 内部泛洪，由 NSSA 内的 ASBR 产生，到 ABR 处再翻译成 Type 5 传播到其它区域。（P 位控制是否翻译，Type 7 到 ABR 后用 Forwarding Address 防环。）

11. 不做 DR 选举：8 台两两建立邻接，邻接数 = `8 × (8-1) / 2 = 28` 条。做 DR/BDR 选举后：DROther 只与 DR、BDR 建 Full，DR 与 BDR 之间也建 Full，共 `2 × (8-2) + 1 = 13` 条。邻接数减少了约一半以上，且每台路由器要维持的邻接数从 7 降到 2~3。

12. 抑制计时器解决的是「坏消息被旧的好消息翻回去」：收到某网段不可达后，180 秒内忽略关于该网段的一切更新（包括看似更优的），避免路由器被邻居的过期通告误导而重新装回失效路由。副作用是：若这 180 秒内该网段其实通过另一条路恢复了，新路由也要等到抑制期结束才被接受，收敛时间被拉长到最长 180 秒。

</details>
